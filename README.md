# AI 单人网页小游戏制作平台

本项目的第二阶段产品定位是：**帮助非程序员通过自然语言完成单人网页小游戏的设计、生成、试玩、修改、验收和发布。**

平台不承诺生成所有类型的游戏。当前目标聚焦于能在现代浏览器中独立运行、以单人体验为主、能够在桌面和手机上完成核心循环的 2D 与有限场景 3D 小游戏。

## 当前可运行功能

根网址保留原有“造界”首页、项目列表和游戏大厅。导航中的“边玩边改”先要求用户从游戏大厅选择具体游戏，再进入 `/player-first?game=<项目ID>`：当前已发布游戏占据主画面，用户从边缘按钮提交一句意见；每个游戏分别保存意见、版本和开发记录，不绑定固定示例。开发过程通过可收起聊天展示。该流程会生成并绑定 AI 位图、建立变更集、生成不可变构建、执行玩法与多设备检查，用户试玩满意后再发布稳定网址或下载完整开源包；它的高级工作台保留当前游戏参数进入 `/player-first?advanced=1&game=<项目ID>`。

第一条 M0 创建链路已经实现：

- 从 14 个成熟玩法中选择改造起点。
- 每个模板提供世界观、美术、内容与小机制四类固定建议。
- 自由要求即时归类为 R0 表现、R1 内容调节、R2 小规则或 R3 核心重写。
- R3 需求不会继续污染旧模板，而是带着原描述转入新游戏设计。
- 新游戏先匹配内部已验证机制，再形成包含真实来源和不可复制边界的参考档案。
- 生成前校验单人网页范围、核心规则、AI 位图资源约束和桌面/触控输入。
- 草稿保存在当前浏览器，可以导出 `GAME_SPEC_V2.json` 和 `REFERENCE_DOSSIER.json`。

本地运行：

```powershell
npm install
npm run dev
```

### Windows 与 macOS 的 AI 位图配置

项目不读取浏览器或项目文件中的密钥。把 `.env.example` 复制为不会被 Git 提交的 `.env.local`，填写 `OPENAI_API_KEY` 后重新启动服务：

```powershell
# Windows PowerShell
Copy-Item .env.example .env.local
npm run dev
```

```bash
# macOS / Linux
cp .env.example .env.local
npm run dev
```

Windows 会依次寻找 `PYTHON`、`python` 和 `python3`；macOS/Linux 会优先使用 `python3`。密钥只传给本机 `imagegen` CLI 子进程，不会写入浏览器、本地项目记录、日志或开源交付包。

质量检查：

```powershell
npm run typecheck
npm test
npm run build
npm run test:browsers
```

## 产品主链路

```text
自然语言创意
  → 支持范围判断
  → 游戏设计合同
  → 可执行规则合同
  → 运行时或实验生成通道
  → 规则测试与真实浏览器试玩
  → 人工体验和主美复核
  → 不可变版本与稳定玩家网址
```

## 当前规划原则

1. 先证明游戏真的能玩，再追求类型数量。
2. 每条发布规则都必须有对应证据，禁止整体检查通过后批量标绿。
3. 调试用的强制胜负钩子只能验证页面状态，不能代替真实玩法路径。
4. 成熟模板、AI 原创游戏和暂不支持需求必须明确区分。
5. 进度不统一强制为 20 关；有限关卡、无尽、单次旅程、回合和章节分别建模。
6. 游戏的核心美术使用可追溯的 AI 位图，交付包禁用 SVG，并完整包含运行所需资源。
7. 平台只承诺已经被黄金游戏和回归测试证明过的能力。
8. 现有模板优先向用户提供安全、具体的改造建议；新游戏优先复用已验证机制，并在改变核心规则前研究真实同类游戏。
9. AI 资源必须直接进入项目并绑定使用位置；每次 AI 修改都要经过同一构建的桌面、手机预览和受影响规则验证。
10. 场景编辑面向游戏对象和安全属性，不向普通用户暴露完整代码编辑器、引擎目录和构建参数。

## 实施状态

当前已经形成从创建入口到制作工作台的可运行纵向版本：

- `game-spec-v2`、v1 迁移、六类进度模式、稳定规则 ID 和验收 ID。
- 完整项目本地保存与恢复，不再只保存创建页草稿。
- AI 位图生成记录、资源版本、场景绑定、失败保留旧版本和本地资源打包门禁。
- AI 位图排队与取消、透明底提取、裁切、尺寸适配、压缩和精灵图拆分。
- DOM、Canvas 与有限 3D 的场景适配；对象层级、安全属性、50 步撤销重做和部件动画联动。
- 不可变构建、规格/代码/资源哈希、GameProbe 真实动作和证据失效。
- 桌面、横竖手机、真机二维码和稳定玩家网址；Chromium、Firefox、WebKit 发布矩阵。
- 真实帧率、P95 帧耗时、输入延迟、长任务、内存、无障碍、音频恢复和截图证据。
- 受影响检查调度、修改前后截图、整组回滚、双视角真人体验门禁和匿名质量事件。
- 包含运行时、全部本地资源、规格、规则、来源与质量报告的 ZIP 导出能力。
- “现有滑动合成改造”和“全新虫虫攀枝”两类完整流程，以及 14 个模板的专属动作回归。
- 队列经营、章节叙事、卡牌连携、单人手柄输入和 WebGL 空间谜题五类独立玩法循环；均通过桌面与手机浏览器回归。

本地 AI 位图生成通过开发服务调用 Codex `imagegen` CLI，使用 `gpt-image-2`。密钥从服务端进程环境或 `.env.local` 读取，不进入浏览器、项目或交付包。当前机器尚未配置该密钥，因此真实图片调用会明确失败并保留旧版本，不会生成虚假占位资源。

逐项完成情况和尚未通过的发布门禁见 [开发完成审计](docs/07-implementation-status.md)。
