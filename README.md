# AI 单人网页小游戏制作平台

本项目的第二阶段产品定位是：**让非专业用户用最少操作，通过自然语言获得设计、资源、玩法、教学、难度和发布均完整的单人网页小游戏。**

最高产品规则：默认创作路径只要求用户表达创意并确认一次关键方案；引擎选择、规则补全、资源匹配或生成、新手帮助、难度递进、质量检查和打包发布由平台自动完成。只有需求存在无法安全推断的冲突时才追问，专业参数只进入可选的高级模式。不得以减少用户操作为由降低游戏完成度，也不得把内部技术选择转嫁给普通用户。

平台不承诺生成所有类型的游戏。当前目标聚焦于能在现代浏览器中独立运行、以单人体验为主、能够在桌面和手机上完成核心循环的 2D 与有限场景 3D 小游戏。

## 当前可运行功能

根网址 `/` 默认显示游戏大厅。大厅只展示平台官方发布的游戏；用户新建或改造的游戏无论是否发布，都只进入 `/projects`“我的项目”。头部只保留两个业务入口：“游戏创作”进入 `/create`，“我的项目”进入 `/projects`；旧 `/games` 地址继续兼容游戏大厅。“边玩边改”不是全站导航入口：玩家从游戏大厅正常开始任意游戏，游戏全屏运行，并在画面边缘提供固定的“改造这个游戏”按钮。点击后才出现一句话意见面板；每个游戏分别保存意见、版本和开发记录。开发过程通过可收起聊天展示。该流程会生成并绑定 AI 位图、建立变更集、生成不可变构建、执行玩法与多设备检查，用户试玩满意后再发布稳定网址或下载完整开源包。

第一条 M0 创建链路已经实现：

- 从 14 个成熟玩法中选择改造起点。
- 每个模板提供世界观、美术、内容与小机制四类固定建议。
- 自由要求即时归类为 R0 表现、R1 内容调节、R2 小规则或 R3 核心重写。
- R3 需求不会继续污染旧模板，而是带着原描述转入新游戏设计。
- 新游戏先匹配内部已验证机制，再形成包含真实来源和不可复制边界的参考档案。
- 生成前校验单人网页范围、核心规则、AI 位图资源约束和桌面/触控输入。
- 草稿保存在当前浏览器，可以导出 `GAME_SPEC_V2.json` 和 `REFERENCE_DOSSIER.json`。

本地运行：

```powershell
npm install
npm run dev
```

### Windows 与 macOS 的 AI 位图配置

项目不读取浏览器或项目文件中的密钥。把 `.env.example` 复制为不会被 Git 提交的 `.env.local`，填写 `OPENAI_API_KEY` 后重新启动服务：

```powershell
# Windows PowerShell
Copy-Item .env.example .env.local
npm run dev
```

```bash
# macOS / Linux
cp .env.example .env.local
npm run dev
```

`npm run dev` 启动时会自动加载 `.env.local`（其次 `.env`）里的变量，已有的环境变量不会被覆盖；生产部署请直接通过进程环境变量或 `OPENAI_API_KEY_FILE` 提供密钥。本机若有系统代理，请在 `.env.local` 里加上 `NODE_USE_ENV_PROXY=1`，否则 Node 的 fetch 不走代理，AI 调用会超时。密钥只在服务端进程内使用，不会写入浏览器、本地项目记录、日志或开源交付包。

质量检查：

```powershell
npm run typecheck
npm test
npm run build
npm run test:browsers
```

## 产品主链路

```text
自然语言创意
  → 支持范围判断
  → 游戏设计合同
  → 可执行规则合同
  → 运行时或实验生成通道
  → 规则测试与真实浏览器试玩
  → 人工体验和主美复核
  → 不可变版本与稳定玩家网址
```

## 当前规划原则

**最高规则：最小操作、高完成度。** 非专业用户默认只需“描述创意 → 确认方案 → 试玩成品”；系统自动完成设计补全、资源、实现、教学、难度、验收和发布准备，确有歧义时才追加必要问题。

1. 先证明游戏真的能玩，再追求类型数量。
2. 每条发布规则都必须有对应证据，禁止整体检查通过后批量标绿。
3. 调试用的强制胜负钩子只能验证页面状态，不能代替真实玩法路径。
4. 成熟模板、AI 原创游戏和暂不支持需求必须明确区分。
5. 进度不统一强制为 20 关；有限关卡、无尽、单次旅程、回合和章节分别建模。
6. 游戏的核心美术使用可追溯的 AI 位图，交付包禁用 SVG，并完整包含运行所需资源。
7. 平台只承诺已经被黄金游戏和回归测试证明过的能力。
8. 现有模板优先向用户提供安全、具体的改造建议；新游戏优先复用已验证机制，并在改变核心规则前研究真实同类游戏。
9. AI 资源必须直接进入项目并绑定使用位置；每次 AI 修改都要经过同一构建的桌面、手机预览和受影响规则验证。
10. 场景编辑面向游戏对象和安全属性，不向普通用户暴露完整代码编辑器、引擎目录和构建参数。
11. 官方游戏只有一个真相来源——登记表 `src/shared/official-games/<id>.ts`：玩法模板、验收场景、运行时定义、机制映射、服务端模板枚举、固定游戏注册、seed 清单和大厅顺序全部由它派生，禁止再手写映射表；新增一款官方游戏按 [docs/55 操作手册](docs/55-adding-an-official-game.md) 的五步做（`npm run game:new` 脚手架 → 填登记与美术溯源 → 实现 → 守卫测试与三浏览器 → 合并后重启自动进大厅）。AI 原创游戏仍按创意描述匹配能力落到玩法模板。

## 实施状态

当前已经形成从创建入口到制作工作台的可运行纵向版本：

- `game-spec-v2`、v1 迁移、六类进度模式、稳定规则 ID 和验收 ID。
- 完整项目本地保存与恢复，不再只保存创建页草稿。
- AI 位图生成记录、资源版本、场景绑定、失败保留旧版本和本地资源打包门禁。
- AI 位图排队与取消、透明底提取、裁切、尺寸适配、压缩和精灵图拆分。
- DOM、Canvas 与有限 3D 的场景适配；对象层级、安全属性、50 步撤销重做和部件动画联动。
- 不可变构建、规格/代码/资源哈希、GameProbe 真实动作和证据失效。
- 桌面、横竖手机、真机二维码和稳定玩家网址；Chromium、Firefox、WebKit 发布矩阵。
- 真实帧率、P95 帧耗时、输入延迟、长任务、内存、无障碍、音频恢复和截图证据。
- 受影响检查调度、修改前后截图、整组回滚、双视角真人体验门禁和匿名质量事件。
- 包含运行时、全部本地资源、规格、规则、来源与质量报告的 ZIP 导出能力。
- 覆盖现有滑动合成改造、机制组合与官方模板的专属动作回归。虫虫攀枝与苔径迷庭已于 2026-09-06 移除，不能再作为官方游戏或改造模板使用。
- 队列经营、章节叙事、卡牌连携、单人手柄输入和 WebGL 空间谜题五类独立玩法循环；均通过桌面与手机浏览器回归。
- 纸境及专用模板已于 2026-09-06 删除；共用引擎保留，范围见 [删除记录](docs/74-retired-official-games.md)。
- 平台**游戏引擎层**（PlayCanvas 2.21.4 底座，`src/engine/playcanvas/`）：引导 / 程序化几何与材质 / GameProjectV3 → 实体树 / 行为注册表 / 规则桥 / 输入 / `__GAME_DEBUG__` / 产物写入的通用封装，立体书是第一个消费者；`examples/engine-playcanvas-demo/` 用一份手写 GameProjectV3 走通“结构化描述 → 可运行、可验收的 3D 游戏”最小闭环。边界、映射规则、已实现行为与 AI 生成接入见 [docs/58](docs/58-engine-layer.md)。

本地 AI 位图生成通过开发服务调用 Codex `imagegen` CLI，使用 `gpt-image-2`。密钥从服务端进程环境或 `.env.local` 读取，不进入浏览器、项目或交付包。当前机器尚未配置该密钥，因此真实图片调用会明确失败并保留旧版本，不会生成虚假占位资源。
