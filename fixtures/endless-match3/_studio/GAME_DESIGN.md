# 自由创想 · 专业游戏设计文档

## 产品定位

- 类型：清爽柔和风无限三消
- 目标玩家：喜欢轻松消除、追求分数与连锁掌控感的休闲玩家，随时开随时停
- 单局时长：2–8 分钟
- 玩家幻想：在柔和的糖果色棋盘上随手拨动方块，看成串消除和连锁一路蔓延
- 设计来源：AI 依据创意定制的设计合同

## 核心承诺

制作一个清爽柔和风格的无限三消最小demo。拖动或点选交换相邻方块，三个及以上相同方块消除、下落补齐并可连锁；无可交换消除时自动洗牌。没有通关、失败、倒计时、生命、等级、教学或关卡扩展，可一直玩；有得分和重新开始。全部画面程序绘制，不生成图片。

## 核心循环

1. 扫视棋盘找可消的相邻对
2. 拖动或点选交换两个相邻方块
3. 三个及以上同色消除并加分
4. 上方方块下落补齐，触发连锁
5. 无可消交换时棋盘自动洗牌

## 胜负条件

- 胜利：无通关目标，玩家自行决定何时停止；分数持续累积
- 失败：无失败条件：不会输，无倒计时与生命，无解时自动洗牌

## 手感与反馈

- 按下方块有轻微放大与柔光描边
- 非法交换会弹回原位，动作可读
- 消除时方块缩小淡出并散出柔色光点
- 下落带小幅回弹，落定后停稳
- 连锁每层递增提示分数飘字
- 洗牌时全盘轻微翻转后重排

## 新手引导

- 无

## 无障碍与输入

- 拖动与点选两次皆可完成交换
- 方块用颜色加不同形状区分
- 触控目标不小于棋盘格全尺寸
- 重新开始按钮常驻且可键盘聚焦

## 制作风险

- 实验性生成玩法:规则代码由模型生成,通过自动验收后仍需试玩确认
- 连锁下落与消除判定需串行排队，避免动画重叠出错
- 洗牌后仍需校验存在可消交换，否则重洗
- 柔和低饱和配色易降低相邻色辨识度

## 硬约束

- 必须以“色块”视觉风格统一改变页面编排、组件造型、字体层级、强烈细节、画布细节与反馈，不能只换配色
- 结束条件：无通关目标，玩家自行决定何时停止；分数持续累积
- 失败规则：无失败条件：不会输，无倒计时与生命，无解时自动洗牌
- 单局节奏：2–8 分钟
- 拖动与点选两次皆可完成交换
- 方块用颜色加不同形状区分
- 触控目标不小于棋盘格全尺寸
- 重新开始按钮常驻且可键盘聚焦

## 验收清单

- [ ] AC-LOAD · P0 · 游戏可以完成首次加载并进入可操作状态
- [ ] AC-INPUT · P0 · 主要输入在桌面和目标手机画幅可操作
- [ ] AC-LOOP · P0 · 核心循环至少能够完整执行一次
- [ ] AC-END · P0 · 胜负或完成条件能够被触发并正确显示
- [ ] AC-RESTART · P0 · 重开会清理旧状态并开始新一局
- [ ] AC-CONSOLE · P0 · 完整流程没有未处理控制台错误
- [ ] AC-STYLE · P0 · “色块”必须同时改变页面编排、组件造型、字体层级、装饰密度、画布细节与反馈动效，不能只换配色
- [ ] AC-FOCAL · P0 · 玩家角色、主要目标或核心棋盘必须成为第一视觉焦点，不能被背景、装饰或界面面板淹没
- [ ] AC-FEEDBACK · P1 · 关键操作、受击或错误、成功与失败都有可区分的即时反馈
- [ ] AC-PACING · P1 · 所选难度会改变真实规则参数，并形成可感知的局内压力曲线
- [ ] AC-ASPECT · P0 · 游戏画布、关卡视野与触控布局必须按玩法合同中的目标比例设计，不能统一强制为方形
- [ ] AC-CAMERA · P0 · 镜头策略必须与玩法和目标画幅匹配，主体不能因全景缩放而失去可读性
- [ ] AC-STATE · P0 · 等待、游玩、关卡完成、胜利、失败与重开状态必须锁定正确的输入范围
