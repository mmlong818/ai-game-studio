# 3D 标识与低配保护

适用：大厅中的所有 3D 作品；自动画质本次接入海岛卡丁车和牧野小火车。其他引擎作品仍需独立接入，不能把提示词规则视为已实现。

- 大厅封面依据 dimensions === 3d 展示 3D 角标，封面加载失败也保留；2D 不误标。
- 三档渲染像素预算为 160 万、100 万、60 万；DPR 同时受设备倍率、游戏上限与像素面积约束。CSS 界面仍以原分辨率显示。
- 检测到不超过 4 核或 4 GB 内存提示时从均衡档开始。硬件提示只辅助初值，不能证明 GPU 性能。
- 排除开始 2 秒采样；连续两个 2 秒窗口的 P90 帧间隔超过 24ms 才下降一档。降档后重新预热，同一会话不自动升档，避免频繁清晰度切换。隐藏页面停止绘制，恢复时重置采样。
- 阴影贴图为 2048 / 1024 / 512，降档释放旧贴图并重新烘焙；装饰粒子为 100% / 70% / 50%，不删除车轮、收集、冲刺、胜利等核心动画。
- 不改变地图、比赛人数、AI、速度、计分或操作方式。两款独立产物各携带模块副本，用一致性测试防止规则漂移，不跨游戏加载代码。

## 可复现检查

- 单元：tests/adaptive-quality.test.ts，覆盖独立实例、DPR 面积预算、单次卡顿不降档、持续慢帧降档与降档下限。
- 标签：src/web/GameLibrary.test.tsx，覆盖 3D、2D 与封面失败。
- 交互：两款既有 browser 测试，覆盖真实操作、暂停、移动端、结算/线路编辑以及资源重建。
- 性能：运行 node node_modules/tsx/dist/cli.mjs scripts/check-3d-performance.ts，输出 output/performance/3d-low-spec.json。1280×720、DPR 2、4 核/4 GB 初始提示、CPU 4 倍限速，赛车实际开始、铁路使用 18 段风景线路；预热 8 秒后采样 12 秒。

限速浏览器不是物理低端 GPU。该记录只能证明所测场景表现，不保证所有机器 60 FPS；真实低端集显、长时间运行与其他 3D 游戏仍需分别验证。以往质量报告中的采样和源码哈希是历史版本证据，不应作为本次变更后的验证。
