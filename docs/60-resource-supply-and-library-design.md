# 资源供给与资产库设计

> 状态：R0、R1 已实施；R2 首批可信来源已进入隔离区并完成精选清单，资源规范化加工待实施
> 目标：解决“已经能加工和绑定资源，但没有稳定、完整、可检索的资源供给”问题。

## 1. 问题判断

资源系统遵循“最小操作、高完成度”：普通用户不需要搜索素材、判断格式、核对许可证、补齐动作状态或手工压缩。平台根据设计合同自动列出资源需求，优先从可信资源族匹配，缺失时生成或提出少量可理解的风格选择，并在后台完成合规、加工、绑定和验收。

当前平台已有 AI 位图生成、透明底处理、裁切、压缩、精灵图拆分、版本、哈希、场景绑定和打包门禁。真正缺失的是：

- 设计阶段没有先产生完整资源槽位，生成到中途才发现缺图、缺状态或缺声音。
- 缺少可持续导入的可信来源池与许可准入规则。
- 资源只有文件角色，缺少语义、风格、视角、动作、状态、性能预算和可替换性描述。
- 2D 单图已有基础，3D 模型、骨骼动画、材质、环境、VFX、UI 套件和声音仍不成体系。
- 官方游戏资产与用户生成资产没有形成可复用但不串风格的“资源族”。

资源工作必须从“找素材”升级为“需求 → 获得 → 规范化 → 评审 → 绑定 → 追溯 → 裁剪发布”。

## 2. 两类资源必须分开管理

### 2.1 开发资源

包括引擎运行库、CLI、MCP、类型声明、官方示例代码、测试夹具、导出器和构建工具。代码许可与示例资源许可分别记录，不因引擎 MIT 就自动允许复制示例中的模型、图片和声音。

### 2.2 游戏内容资源

包括：

- 2D：角色、敌人、道具、地块、背景、UI、图标、序列帧和特效图。
- 3D：模型、骨骼、动作、材质、贴图、HDRI、模块化场景件、碰撞代理和 LOD。
- 音频：UI、合法/非法操作、奖励、受击、胜负、环境、循环音乐和语音。
- 设计内容：教程文案、关卡数据、提示、失败建议、任务、事件和难度参数。

## 3. 资源需求合同

设计确认后、生成或搜索前，必须产生 `AssetRequirement[]`：

```ts
interface AssetRequirement {
  id: string;
  role: string;
  mediaType: "image" | "spritesheet" | "model" | "animation" | "material" | "audio" | "font";
  usage: { sceneIds: string[]; objectIds: string[]; stateIds: string[] };
  visual: { styleFamily: string; view?: string; palette?: string[]; transparency?: boolean };
  technical: { formats: string[]; maxBytes: number; dimensions?: string; lods?: number };
  variants: string[];
  requiredFor: "prototype" | "review" | "publish";
  fallbackPolicy: "procedural" | "previous-version" | "block-build";
}
```

每个玩家角色至少声明 idle、move、action、hurt、win、lose；每个交互对象声明 normal、hover/target、active、disabled/destroyed。不存在对应玩法状态时显式标记不需要，禁止静默缺失。

## 4. 来源优先级

1. **项目原创或委托制作**：用于正式品牌角色、关键 UI、核心场景和宣传图。
2. **平台生成资源**：用于与玩法和风格强绑定的角色、背景、特效与变体；保存模型、提示词、输入参考、时间和加工链。
3. **CC0 基础库**：用于原型、材质、HDRI、环境件和通用道具。优先 [Poly Haven](https://polyhaven.com/license) 与 [Quaternius](https://quaternius.com/faq.html)。
4. **可归属资源**：CC BY、OFL 等允许商业使用且义务可自动履行的资源，必须生成 attribution。
5. **商店或订阅资源**：逐包审查是否允许再分发到开源交付包；默认不进入用户可下载的源资源库。
6. **用户上传**：要求用户确认权利来源，进入隔离区扫描后使用。

开放站点不等于每项资源同一许可。例如 Freesound 同时存在 CC0、CC BY 和 CC BY-NC，且其 API 商业使用另有条件，必须逐项判断。[Freesound 许可说明](https://freesound.org/help/faq/)

## 5. 许可准入矩阵

| 许可/状态 | 商业游戏 | 开源交付包 | 默认处理 |
| --- | --- | --- | --- |
| CC0 | 允许 | 允许 | 自动准入，仍保存来源和作者 |
| CC BY | 允许 | 允许 | 自动生成署名后准入 |
| OFL 字体 | 允许 | 允许 | 保留许可证与字体名称限制 |
| MIT/Apache 代码 | 允许 | 允许 | 仅适用于代码；保留 notice |
| CC BY-SA | 条件允许 | 条件允许 | 人工法务/产品复核，不进入默认库 |
| CC BY-NC、NC | 不允许商业 | 不允许 | 拒绝正式项目 |
| ND | 不适合加工 | 不适合 | 拒绝进入派生流水线 |
| 无许可证、来源不明 | 不允许 | 不允许 | 隔离并阻止绑定 |
| 商店自定义许可 | 逐项判断 | 通常受限 | 人工审核并限制导出范围 |

## 6. 资产记录模型

在现有 `GameProjectV3.resources` 外增加来源和版本实体：

- `ResourceSourceRecord`：来源 URL、作者、获取时间、许可证 ID、许可原文哈希、署名文本、商业/修改/再分发权利、人工审核人。
- `ResourceVersion`：原始哈希、派生哈希、加工步骤、尺寸、时长、面数、贴图通道、压缩格式、缩略图/转台预览和质量状态。
- `ResourceFamily`：同一风格与用途下的一组角色、环境、UI、声音和变体，防止跨包混搭。
- `AssetBinding`：资源版本绑定的对象、状态、动画、规则反馈和设备变体。

发布包继续只包含最终绑定版本；来源原文、署名和加工记录写入 `_studio/RESOURCE_PROVENANCE.json`。

## 7. 入库流水线

```text
资源需求合同
  → 内部库语义检索
  → 选择生成 / 采购 / 开放资源 / 用户上传
  → quarantine 隔离区
  → 许可与敏感内容检查
  → 格式、尺寸、坐标、音量、面数规范化
  → 派生缩略图 / 接触表 / 转台 / 波形预览
  → 风格、角色、状态、技术标签
  → 人工视觉或听觉复核
  → 绑定 GameProjectV3
  → 浏览器实际渲染验收
  → 冻结进入不可变构建
```

禁止直接热链外部 URL。所有发布资源必须进入项目、校验哈希并可离线运行。

## 8. 首批资源库目标

首批不追求数量最大，而要覆盖黄金游戏的共同缺口：

- 6 个完整 2D 风格族，每族至少 1 套 UI、1 个玩家、4 个危险/敌人、6 个交互物、8 个反馈状态和背景层。
- 3 个低多边形 3D 场景族：自然、城镇、科幻；每族至少 20 个模块件、10 个道具、3 个机关、碰撞代理和两级 LOD。
- 2 套通用角色骨骼与动作族：idle、walk/run、jump、hit、interact、win、lose。
- 1 套统一 UI 功能资源：开始、暂停、重试、提示、设置、音量、触控、胜负、关卡和无障碍状态。
- 至少 80 个短音效，覆盖 UI、移动、碰撞、收集、危险、奖励、胜负和环境；首批只用原创、CC0 或权利清晰的委托资源。
- 12 段可循环音乐/环境底床，按紧张度和题材标记，不按游戏标题硬绑定。

每个资源族都必须有一款黄金游戏实际使用并通过浏览器、手机和发布包检查，才能进入平台推荐库。

## 9. 资源检索与生成决策

检索评分由以下部分组成：玩法角色 30%、风格族 25%、状态/动作 20%、技术预算 15%、许可 10%。许可不通过时总分直接归零。

- 找到同风格、同动作、同技术预算资源：优先复用。
- 找到结构合适但风格不符：作为生成参考，不直接混入正式游戏。
- 角色和关键反馈：默认生成或原创。
- 通用环境件、材质、HDRI：优先可信开放库。
- 缺失资源不得用无关图标或文字占位伪装为完成；原型可用程序化占位，但发布门禁必须失败。

## 10. 实施切片

1. R0：已实现 `AssetRequirement`、`AssetBinding` 与资源缺口报告，从设计合同自动列出背景、UI、机制状态、教学覆盖层和反馈音频；发布资源没有显式批准绑定时稳定失败。
2. R1：已实现来源/许可记录、隔离状态机和 CC0/CC BY/OFL 自动门禁；未知、NC、ND、错误套用代码许可稳定拒绝，SA 与商店自定义许可进入人工复核。
3. R2：已从 Kenney 官方资源页接入固定哈希的 Nature Kit、Puzzle Pack 1、UI Pack 和 Interface Sounds；首批资源库包含 26 个 GLB、86 个益智 PNG、82 个统一 UI PNG 和 100 个 OGG，原包保存在本地隔离目录。导入器在解压前校验归档哈希、许可原文、路径、单文件及总展开体积，并排除 SVG、SWF 和未选择内容。Poly Haven 资产本身虽为 CC0，但当前在线 API 条款限制商业 API 使用，因此只保留人工单项导入候选，不接入默认在线检索。
4. R3：已实现资源族 Schema、语义检索和本地预览；按玩法角色 30%、风格族 25%、状态 20%、技术预算 15%、许可 10% 输出可解释评分，许可或基础兼容性失败时归零，状态不全不能自动绑定。2D 族生成接触表，音频族生成代表波形，3D 族使用本地 Three.js 生成 26 模型接触表和旋转 WebP，预览不依赖外部网络。
5. R4：默认创作接线已实施为影子模式：项目创建和重建都会先按策划机制、教学步骤、维度和视觉风格生成需求并检索资源族，决策随 `GameSpec` 保存，构建包写入 `_studio/RESOURCE_PLAN.json`。已复核但未通过黄金游戏的资源只建议复用；缺状态时明确补生成；替换会列出受影响机制、教学步骤和需要重跑的验收。
6. R5：研究候选资源取得计划已接线。建立或重新运行研究沙箱时，系统会用正式精选库逐项检索资产需求，并固定输出“已有可复用、程序生成、需要采购、需要创作”四类路线；库内复用必须携带来源、许可 ID 和核验状态，采购必须标记许可待复核，平台生成或自制必须标记为项目所有。计划写入研究任务和 `_studio/RESOURCE_ACQUISITION_PLAN.json`，工作台可展开查看，但计划完成不会伪装为资源已入库。
7. R5.1：内部研究护照可把整份取得计划一键转换成幂等保存的 `research-resource-acquisition-task-v1`。每项分别进入“原型已准备、待绑定批准、待许可复核、待资产复核”，并携带候选路径、许可快照、缺失状态、交付物、检查清单和完成条件。系统不会自动购买或接受第三方条款，也不会把任务生成当成素材取得；重新生成隔离原型时同步归档 `_studio/RESOURCE_ACQUISITION_TASK.json`。
8. R5.2：资源执行任务已加入逐项“提交成果 → 独立批准或退回 → 修正后重提”状态链。复用与创作必须提交资源文件、视觉复核和运行报告；程序生成必须提交生成配置、实际产物、视觉复核和运行报告；采购还必须提交许可记录及已核验的许可 ID、官方来源和履行义务。每次提交与复核均保留不可变历史，全部工作项批准后整批任务才会标记完成。
9. R5.3：已批准成果可以从最新自动验收沙箱一键写入独立隔离区。导入器先读取全部真实文件，检查路径、文件头、合同媒体类型和总大小，计算 SHA-256 并生成短稳定资源 ID；整批完全通过后才以不可覆盖方式落盘，避免失败时留下半套文件。程序生成路线除配置外必须提交实际生成产物。隔离批次先生成 `reviewed` 绑定和可复核预览引用，恶意内容与敏感内容检查均明确通过后才升级为 `approved`；任一失败会拒绝整批。批次、检查结果与绑定同时写回研究任务和资产需求合同。
10. R5.4：安全批准的隔离资源可晋升为磁盘持久化、重启可重新加载的 `research-resource-family-v1`。研究资源族支持多个来源和许可义务，单独保存语义资料并立即进入资源检索；生命周期固定为 `reviewed`，黄金游戏验证前不能自动绑定。图片资源由真实文件生成接触表，音频由 Chromium 解码后生成真实波形，GLB 由 Three.js 实际加载后生成八视角转台，字体等待 `document.fonts.ready` 后生成中英数及界面词字形页。四条派生路径均用真实 PNG、OGG、GLB 和 TTF 样本通过测试；混合媒体资源族会在落盘前阻断。
11. R6：用两款 2D 与一款 3D 黄金游戏完成全链验收。

## 11. 完成标准

- 默认流程不要求非专业用户理解文件格式、尺寸、面数、许可类别或资源绑定；用户最多确认整体风格和关键角色形象。
- 创建游戏前可以准确回答需要多少项资源、哪些已有、哪些必须获得。
- 任一发布资源都能追溯到来源、许可、原始文件、加工步骤和绑定位置。
- 正式包没有远程资源、未知许可、未使用历史版本和本机路径。
- 替换资源后，受影响的对象、状态、视口和验收自动失效并重跑。
- 资源丰富度提升不能以风格混乱、包体失控或规则不可读为代价。
