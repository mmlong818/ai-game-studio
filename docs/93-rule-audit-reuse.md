# 规则审核回执复用

2026-09-07。本文描述代码行为；是否真的减少了某次任务的调用次数，以该任务的 `_studio/GENERATION_ATTEMPTS.jsonl` 与 `RULE_FIDELITY.json` 记录为准。

## 问题

修复版本复用同项目上一版完整代码并重新验收时，代码模型不再调用，但逐条规则审核仍每次向模型付费。真实翻牌样本的三次局部布局修复各执行了一次规则审核（见 [91](91-real-creation-closure.md)）；其中代码未变、只重新验收的情形本可以不再付费。

## 行为

- `RULE_FIDELITY.json` 升级为 `schemaVersion: 2`，新增 `sourceSha256`：被审核代码经 `readGeneratedSource` 复原后的 SHA-256。复原失败时不写该字段，该回执不能被复用。
- 制作流程只在以下条件同时成立时复用上一版审核，不调用审核模型：
  1. 本次走“确认合同未变、复用候选构建代码”路径，且候选构建就是审核回执所在的构建；
  2. 本次要审核的代码与候选回执的 `sourceSha256` 逐字节一致；
  3. 由当前确认方案派生的规则清单与回执中的规则逐条、按序一致；
  4. 回执中每条规则均为已实现，`implemented === total`，时间戳合法。
- 未通过、不完整、旧版本（v1）、损坏或缺少哈希的回执一律不复用；此时照常调用审核模型，审核不可用仍按 [92](92-production-safety-and-review.md) 停止生图与交付。
- 复用时新版本仍写入自己的 `RULE_FIDELITY.json`，附 `reusedFromBuildId`；`GENERATION_ATTEMPTS.jsonl` 记录 `rule-audit-reused` 及来源构建。制作步骤文案明示“复用构建 … 的审核结果，本次未调用审核模型”。
- 只复用审核结论，不跳过静态探针与真实浏览器验收。审核回执不是美术审核，也不是可玩性证明。

## 边界

- 第二轮定向修正后的代码与上一版不同，不会复用。
- 资产阶段的旧版 `setup-start` 控件迁移若改写了页面或脚本，复原哈希会变化，后续复用失败并回落到付费审核；这是安全方向，不是静默通过。
- 这不构成金额级预算或外部调用对账，也不改变每任务 3 次代码生成请求上限。

## 验证

`src/server/rule-audit-checkpoint.test.ts` 覆盖一致复用、哈希／规则／顺序不一致、未通过、不完整、v1、损坏与缺失文件；`src/server/build-orchestrator-repair.test.ts` 新增复用路径不调用代码模型与审核模型、代码不同则照常审核两项。测试使用模拟审核器，不调用付费 API。
