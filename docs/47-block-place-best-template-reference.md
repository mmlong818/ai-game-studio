# 果冻填阵最佳模板参照与实现合同

## 1. 目标与边界

本轮把 `block-place` 从“能拖动并消行的演示”提升为可复用的商业级块放置模板。麻将 v39 冻结，不在本轮修改范围内。

模板必须让玩家在手机 9:16 内完成完整循环：观察三枚候选 → 抬起并预览落点 → 放置 → 横行/竖列消除 → 连击或空间危机 → 完成关卡或无路可走。页面视觉不能继续使用厚黑框、随机彩色边角和高饱和侧栏；棋盘、候选与分数是唯一主要层级。

## 3. 当前真实检查

2026-08-30 打开当前稳定版本 v16 并实际进入 `playing`：

- 成立：8×8 棋盘、三候选、大尺寸候选、横竖消除、连击、提示、20 关入口、无路可走分支。
- 阻碍：页面仍被厚黑框、复古彩色角标和高饱和蓝侧栏主导，背景与游戏主体不属于同一视觉系统。
- 候选块虽然放大，但三张大矩形选择框仍抢占注意力；选中态依赖外框，不像拿起一个真实构件。
- 手机拖动没有明确“抬高手指上方”的合同，手指可能遮住构件和落点。
- 20 关主要依赖分数倍率与难构件概率，缺少可辨认的关卡任务、独立开局和机制章节。
- 没有把当前三枚候选、棋盘和关卡内进度作为可恢复长局保存。

## 4. 规则合同

- 棋盘固定 8×8；每批固定三枚不可旋转构件，用完后刷新。
- 候选生成必须通过递归模拟，保证当前批次至少存在一种连续放完顺序；如果超出尝试上限，使用明确标记的安全回退批次。
- 放置后同时检查完整横行与竖列；交叉格只消除一次，但横竖各计为一条线。
- 拖动时构件在手机上抬高约 1.5–2 格，手指不遮住落点；棋盘显示完整构件幽灵，不只显示单格光标。
- 合法预览使用低透明度构件原色与清晰外轮廓；非法预览使用暖红轮廓，不改变棋盘。
- 三枚候选不再放进三个厚边矩形卡片；使用安静底座、编号和小型选中光环。绿色构件与底座对比度至少 4.5:1。
- 一次多线消除、连续回合消除和清空棋盘分别有不同反馈；不使用遮挡棋盘的大图标闪屏。
- 无任何候选可放才失败；不能在仍有合法落点时提前结算。

## 5. 二十关与模式

五章、每章四关；难度可以多关一级，不强制每关单调上升：

1. 空间感：基础横竖消除、短条与小转角，2 次提示。
2. 三块规划：要求在刷新前放完三块，并开始记录批次完整率。
3. 连击节奏：加入连续消除任务和更长构件，提示减为 1。
4. 危机管理：以独立开局纹样压缩空间，要求从边缘恢复通道。
5. 最终掌握：复杂构件比例提高，要求同时满足分数、消除线数或连击任务。

启动页提供：

- 旅程：20 关、星章、逐关解锁和局内恢复。
- 无尽：保留个人最佳成绩，不以关卡分数目标强制结束。
- 每日：使用日期种子生成确定性开局与候选；同一天重开仍是相同题面。

## 6. 视觉与声音合同

- 方向：轻盈、软萌、果冻材质，但高光和纹理只出现在构件内；工作台使用低饱和暖灰或奶油色。
- 棋盘：占手机可用宽度的 88%–94%，保持正方形，不被面板压缩。
- 候选：位于棋盘下方，单枚构件的可见尺寸不低于 44px；构件轮廓比装饰底座更强。
- 顶部只保留本关目标、分数/消除线和连击；帮助、模式、难度全部留在启动页或返回后。
- 放置声、消除声、连击升级声、非法放置声、失败/完成声必须可区分；环境音乐不能盖过消除节奏。
- 视觉反馈遵守 `prefers-reduced-motion`，减弱动效时仍用轮廓、颜色和文字表达结果。

## 7. 放行验证

- 20 关拥有 20 个不同名称、目标参数和开局签名；五章机制递进可从运行时读取。
- 连续生成至少 100 批候选，递归求解器均确认存在放完三块的顺序。
- 真实指针从候选拖入棋盘，合法预览出现、放置生效；非法拖动不改变棋盘。
- 同时完成一行一列时，交叉格只计一次；多线、连击、清空棋盘反馈均可达。
- 旅程完成至少 3 局、触发 2 次失败；刷新恢复棋盘、候选、分数和关卡进度。
- 无尽和每日模式可从启动页选择；每日种子同日重开一致。
- 390×844 与 1280×720 无遮挡、无拉伸、无横向滚动；按钮与可点候选不小于 44px。
- 控制台、资源请求和状态机无错误；稳定网址只在自动质量与主美复核通过后更新。
