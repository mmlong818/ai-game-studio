# 制作进度的流式展示

2026-09-08。本文描述代码行为。展示的是正在生成的内容片段，不是产物，也不代表验收结论。

## 起因

"生成可玩核心"一步通常要 3–8 分钟：模型写代码、真实浏览器验收三种画幅、模型逐条审核规则，失败还会进入第二次修正。此前页面只显示一句"正在生成游戏代码，第 1 轮，已收到 N 个字符"和一个计时器，浏览器验收和规则审核期间文字完全不动，用户无法判断是在推进还是卡住。

## 行为

- `build_steps` 新增 `live_excerpt` 列（PostgreSQL 用 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`，SQLite 测试库同步建列）。`reportStepProgress(buildId, sequence, detail, excerpt)` 每次都整体写入：不带片段的进度会清空旧片段，避免代码尾巴挂在"正在浏览器验收"上。`BuildStep` 契约新增可选 `excerpt`。
- 代码生成流式回调改为 `(count, progress)`，`describeGenerationProgress(content)` 把收到的 JSON 转义文本解码成最后几行真实代码（≤260 字符、≤4 行），并判断当前写到哪一部分：页面骨架 → 界面结构 → 界面样式 → 游戏逻辑 → 实现说明。进度文案形如"第 1 次制作 · 初次生成：正在生成游戏代码，第 1 轮 · 正在写游戏逻辑 · 已收到 12,345 个字符"，片段随之落库。
- 浏览器验收 `inspectGeneratedGameInBrowser` 新增 `onProgress`，每进入一种画幅上报"正在真实浏览器中检查第 k/3 种画幅 phone-small（360×640）：加载、开局、教学、关卡、结算与重开"。进度写入失败不影响验收结果。
- 规则审核前上报规则条数与预计时长（"正在逐条核对 17 条方案规则……通常需要 1–3 分钟"）。
- 前端：制作页 `AutomaticProduction` 与项目页 `ProjectStudio`（当前进展摘要与步骤列表）在运行中步骤下方渲染 `LiveExcerpt`——等宽、只留尾部几行、光标闪动，并注明"只显示最后几行，完整代码在制作完成后可查"。进度流仍是 750ms 轮询的 ndjson，字段变化即推送。

## 制作页改为工作台布局

制作页（`/create?production=…`，`AutomaticProduction`）不再是单栏说明页，而是与项目页相同的工作台：左侧是游戏位，右侧是进度面板。

- 左侧 `workbench-preview`：按项目画幅自动选择手机框或桌面框（不提供切换按钮，制作中的页面不放任何操作入口），制作中显示占位——当前步骤标题、进展说明与正在写入的代码片段；完成后原位换成隔离试玩 iframe；失败时说明已停在哪一步。
- 右侧 `workbench-panel`：标题与状态点、"当前进展"摘要、错误与同方案重试（仅创建阶段失败且未生成项目时）、准备阶段事件、共用的 `BuildStageList` 步骤列表（编号轨道、动作标签、状态图标、步骤结果），底部进度条。
- `BuildStageList`、`StepIcon`、`StepKindIcon`、`stepActionLabels` 从 `ProjectStudio` 抽到 `src/components/BuildStageList.tsx`，两页共用；项目页在步骤内显示片段，制作页把片段放在左侧游戏位里，不重复。
- 站点头部保留在上方，工作台高度为视口减去头部，右侧进度流自行滚动，左侧手机框按容器高度取尺寸；窄屏改为上下堆叠。
- 原有行为保持不变：制作中没有按钮或链接、完成后只有"继续完善这个游戏 / 查看我的游戏"、失败后只有查看记录入口、错误文案人话化并保留详情、刷新不重复提交。`AutomaticProduction.test.tsx` 10 项与 `ProjectStudio.test.tsx` 全部通过。

## 失败后的重新制作

构建失败（项目已存在）后，制作页与项目页都提供"重新制作这个游戏"按钮：调用 `POST /api/projects/{id}/build` 在同一项目上开新构建，沿用已确认方案，图片走检查点复用不再付费，代码按编排器既有逻辑恢复上一版并针对失败原因修正。它是用户的明确点击，平台仍然不自动重试任何付费调用；按钮旁写明用量后果，并保留"查看已保存的项目与问题"入口。创建阶段失败（尚未生成项目）仍走原有"用同一方案重新制作"回执重提。`AutomaticProduction.test.tsx` 覆盖：点击前不调用 `startBuild`，点击后只调用一次且不重新创建项目。

## 边界

- 片段来自模型流式输出的尾部，可能截在半行；它只表明生成仍在进行，不能据此判断代码质量。
- 规则审核本身是一次非流式模型调用，审核期间只有条数与预计时长，没有逐条实时结果。
- 本次未改构建的总时长与修正轮数；用户仍需等待，只是能看到在等什么。
