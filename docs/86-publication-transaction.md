# 发布状态的一致性边界

2026-09-07

## 根因

旧实现先在事务外读取质量与人工审核状态，随后才开启事务更新公开版本。两者之间若审核结论或归档状态变化，发布可能使用过时快照。页面按钮禁用不能防止该时序问题。

## 修正

发布事务内按项目、版本顺序加锁，重新读取归档状态与目标版本质量、美术结论，再更新 publication 和 project。PostgreSQL 行锁与人工复核的版本锁协调；项目锁串行化发布切换并与归档更新协调。前置快速校验保留，但不再作为最终授权依据。

如果复核失败已先提交，发布重检后拒绝；如果发布先获得锁并成功提交，之后的复核不会自动撤销已经发生的发布。本批不增加自动下线策略，避免擅自改变公开作品。锁保护的是提交时一致性，不是永久保证审核结论不变。

## 验证

类型检查与 8 项服务端专项测试通过。新增 3 项定点时序/故障测试：审核改为未通过、项目被归档、切换后写项目状态失败；均保留旧公开版本。这些测试在内存 SQLite 中运行，没有发布真实游戏。

后续补充了真实 PostgreSQL 独立连接并发验证，见 [PostgreSQL 发布并发验证](87-postgres-publication-concurrency.md)。多进程并发压力验证仍待补充，不将独立连接测试描述为已完成压力测试。
