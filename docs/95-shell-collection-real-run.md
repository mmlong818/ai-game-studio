# 真实创作第二轮：海边贝壳收集

2026-09-07 晚，用户授权使用付费额度跑完整创作流程：文本走本机 Claude Code CLI 订阅额度（`opus`，见 [94](94-claude-cli-text-provider.md)），图片走 OpenAI `gpt-image-2`。本文只记录实际发生的事实与由此修正的平台问题；未完成的环节不写成完成。

## 样本

- 创意：海边贝壳收集，点击贝壳装进篮子，五关配额递增，无倒计时、无失败。
- 方案由 Claude 在 48 秒内流式生成并在页面确认；浏览器记录中策划与制作各只发出一次 POST。方案冻结为 `generatedCampaign`：5 关、里程碑 1–5、无失败，难度维度 `shellQuota / spawnIntervalSec / shellRadiusPx / shellTypeCount / waveWashIntervalSec / rareShellChance`，其中半径 44→26px、退潮间隔 10→6 秒是**递减**维度。
- 项目 `4af91723-4895-4f3b-8039-739f8ea30d95`。

## 暴露并修正的平台问题

1. **中文教学标签撞成重复机制 ID**（首个任务 `bd47de87…` 在“正在保存游戏项目”失败：`ID 重复：3`）。`stableId` 把中文标签归一后只剩数字，两条含“3”的标签得到同一 ID。修正：无字母或重复的 ID 改用位置回退 ID；回归见 `from-legacy.test.ts`。
2. **创建阶段失败后没有免策划的重试入口**。用户只能回到创作页重新策划付费。新增 `POST /api/production-jobs/:id/retry`：仅对已失败且尚未生成项目、且带已确认方案的任务开新回执；制作页出现“用同一方案重新制作”。已生成项目的构建失败不提供该入口，仍走项目页新版本。
3. **Claude CLI 适配器把工具调用前的说明文字当成内容**（构建 `09a85fa8…` 失败：`"I'll build"... is not valid JSON`）。修正：要求结构化输出时只转发 `input_json_delta`，并在系统提示中要求直接给出结构化结果。该次 Opus 调用约 10 分钟未产出可用代码。
4. **验收把“数值下降”当成违规，与确认方案矛盾**（构建 `7779da5f…`）。第一轮浏览器验收拒绝半径 44→34 等递减；模型在第二轮把半径固定为 36 以通过，规则审核随即判定“未按 44→26 递减”。两项检查互斥，任何实现都无法同时通过。修正：非旧版方案只要求同一维度全程方向一致（递增或递减均可），生成提示同步改写；旧版二十关方案保持原“不下降且步长 ≤0.12”。
5. **“方向一致”检查把 0 当成数值**（构建 `943abf96…`）。退潮从第 3 关才启用，序列 0、0、10、8、6 被判为“既上升又下降”。修正：0 视为该规则尚未启用，方向一致性只看启用后的各关。该构建第一轮复用上一版代码直接通过了浏览器验收，说明前述递减修正有效；规则审核仍要求补齐“海鸥庆祝”的可见形象与半径递减，触发一轮修正。
6. **修改方案因模型多给一条无障碍说明而整体作废**（修改构建 `77072462…` 十秒内失败：`accessibility` 超过 6 条）。模型偶尔超出条数上限；此前入口 schema 直接拒绝，用户看到“修改方案未能完成”。修正：入口只校验下限，超出合同上限的条目按顺序截断（回归见 `design-contract.test.ts`）。
7. 策划提示要求 `rationale` 面向玩家书写，不再出现 `failurePolicy为forbidden` 这类字段名（首轮方案页曾直接显示）。

## 结果

- 构建 4（`10180d72`）成功：复用上一版修正后的代码，未再调用代码模型；规则审核 9/9 通过（`RULE_FIDELITY.json` v2，含源码哈希）；封面与局内背景由 gpt-image-2 生成；浏览器验收通过后冻结为 v1。`GENERATED_CODE.json` 记录模型为 `claude-cli:opus`。
- 真实试玩（普通指针输入，未使用 probe 调试接口）：桌面 1366px 在制作页内嵌试玩中连续装满 3/6/10/15/22 枚，走完五关；手机 390px 直接打开版本地址完成前三关，无横向溢出。结算画面显示海鸥庆祝、贝壳图鉴与下一关入口。
- 试玩中发现两处呈现问题，尚未修复：手机端结算标题被顶部固定 HUD 遮住一截；平台教学提示条（“已跳过教学 · 重看”）在手机上盖住游戏底部“下一枚”按钮。前者属于生成代码布局，后者属于平台教学层。
- 修改流程：在项目页提交“增加鼓励文字、金贝更亮”意见，确认后浏览器只发出一次 `POST /api/projects/:id/revisions`。首个修改构建 `77072462` 因上文第 6 项在方案阶段失败（未调用代码或图片）；修正后以同一意见重新提交，构建 `3efa2283` 成功：方案修订 1 次、代码迭代 2 次（第二次由规则审核触发）、规则审核 2 次，图片按 `ART_REUSE.json` 复用 v1 资源、未再生图。手机端结算面板出现“这片海滩收拾干净了！”鼓励语。
- 正式审核与发布：未带或带错误 `x-studio-review-token` 的审核请求返回 403；未审核版本的发布被拒（现返回 409，此前为 500）。持有本机配置凭据的审核端对 v2（版本号 3）提交通过结论后，发布成功：稳定地址 `http://127.0.0.1:4313/play/game-b5924f1f/`，项目状态 `published`。游戏大厅只展示官方游戏，该作品只出现在“我的项目”。
