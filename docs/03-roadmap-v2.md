# 二次规划：实施路线图

## 1. 总体策略

二次规划的首要任务不是继续增加游戏数量，而是把现有平台从“模板和页面检查”升级为“规则可执行、证据可追溯、AI 原创玩法可真实验收”的系统。

实施顺序遵循：

```text
产品边界
  → Game Spec v2
  → 规则与证据引擎
  → AI 原创玩法验收
  → AI 资源与场景编辑闭环
  → 多设备预览与修改验证
  → 成熟模板迁移
  → 新品类扩展
```

## 2. P0：发布可信基础

### M0：产品口径统一

产物：

- 产品名称统一为“AI 单人网页小游戏制作平台”。
- 创建页、README、帮助和错误提示使用相同支持边界。
- 需求分析结果明确显示完整支持、实验支持或暂不支持。
- 移除“支持所有游戏”或等价的无条件承诺。
- 创建页先展示与当前模板匹配的 3–5 个固定改造建议，再提供自由输入。
- 自由输入自动分类为 R0 换表现、R1 内容与数值、R2 小规则扩展或 R3 核心重写。

退出条件：

- 用户在开始构建前能知道能力边界和实验风险。
- 超出范围的创意不会进入伪成功构建。

预计规模：小，约 2–4 个工程日。

### M1：Game Spec v2 与迁移

产物：

- 新增产品意图、能力、生命周期、动作、实体、资源、规则、不变量和进度模型。
- 规则和验收项使用稳定 ID。
- 支持有限关卡、无尽、单次旅程、回合、章节和沙盒。
- 旧项目读取时迁移到 v2，原始 v1 规格仍可审计和回滚。
- 新增模板改造来源、锁定核心规则、复用能力和参考资料档案字段。

退出条件：

- 至少选取俄罗斯方块、虫虫攀枝、肉鸽麻将和 3D 收集四种差异玩法完成 v2 表达。
- v2 Schema、迁移、序列化和数据库往返测试全部通过。
- 不再存在全品类强制 20 关的字段约束。

预计规模：中，约 1–2 周。

### M2：验收证据绑定

产物：

- 每个验收项绑定规则 ID、检查器、输入动作、断言和证据。
- 构建结束时按 ID 更新状态，删除非视觉项目批量标绿逻辑。
- 报告记录 `specHash`、`codeHash`、`assetManifestHash` 和检查器版本。
- 哈希变化后旧验收自动失效。
- 规则审计缺失、过期或失败时阻止正式发布。

退出条件：

- 能故意破坏一条规则，并只让对应验收项失败。
- 修改美术不会无故失效纯规则证据；修改规则会正确失效相关证据。
- 不允许出现设计已改为瓢虫、规则报告仍验证赛车却显示全绿的情况。

预计规模：中，约 1–2 周。

### M3：AI 原创玩法真实验收协议

产物：

- 统一 `GameProbe`：状态、可用动作、执行动作、种子、重开和快照。
- 生成器同时生成规则实现和验收场景。
- 测试器执行合法动作、非法动作、资源变化、失败、恢复和正常完成。
- `forceWin/forceLose` 降级为结算表现辅助检查。
- 随机生成游戏支持批量种子、公平性和可达性断言。

退出条件：

- “虫虫攀枝”能够自动验证四向移动、头部拾取、露珠爆开、普通碰撞、冲刺破树脂、背景下移、速度断层和安全通路。
- 破坏其中任意一项会稳定阻止发布。
- AI 原创游戏的质量报告不再只有状态机、布局和控制台三类通用检查。

预计规模：大，约 2–3 周。

## 3. P1：体验质量与新品类准备

### M4：AI 资源生成到项目绑定

产物：

- 统一 AI 位图生成记录，保存资源角色、生成参数、模型、来源、加工步骤、版本和内容哈希。
- 生成结果直接进入项目资源库，并能绑定角色、背景、障碍、收集物、特效和界面状态。
- 支持裁切、透明背景、尺寸适配、压缩和精灵图拆分；全过程保持位图约束，不引入 SVG。
- 资源重新生成和替换使用版本化事务，失败时自动保留上一个健康资源。
- 打包时只收集当前场景真实引用的本地资源，同时生成完整来源清单。

退出条件：

- 用户可以用一句自然语言替换角色或场景，预览中立即使用新资源，不需要下载和手工搬运文件。
- 删除或替换资源时，平台能列出受影响对象和画面，不产生 404、空白贴图或历史底图残留。
- 正式包不包含远程图片地址、未使用历史版本、密钥或本机路径。

预计规模：中到大，约 2–3 周。

### M5：场景、层级与属性联动

产物：

- 为 DOM、Canvas 和有限 3D 运行时建立统一的可编辑场景节点模型。
- 画面选中、层级树和属性面板保持同一选中对象，显示对象名称、玩法角色、位置、尺寸、层级、碰撞、动画和资源绑定。
- 普通用户只看到经过规则合同允许的安全属性；核心规则和危险参数保持锁定并说明原因。
- 角色造型、碰撞体、可动部件和历史底图分别建模，避免固定腿、重复障碍和错误锚点混在同一张图中。
- 手机端使用画布优先的底部抽屉或全屏编辑步骤，不让属性面板遮挡关键画面。

退出条件：

- 不读代码也能从画面选中“角色头部”“可动腿”“露珠”“树脂障碍”和“背景层”，并理解它们的作用与绑定关系。
- 调整安全属性后，桌面和手机画面、碰撞和动画锚点保持一致。
- 修改核心规则所依赖的属性时，工作台明确转入规则修改与重新验收，而不是静默破坏玩法。

预计规模：大，约 2–3 周。

### M6：不可变构建与多设备预览

产物：

- 一键生成不可变预览构建，记录规格、代码、资源和检查器哈希。
- 工作台内提供桌面、竖屏手机和横屏手机预览，并生成可在真实手机浏览器打开的临时链接或二维码。
- 预览、正式发布、回滚和开源包复用同一构建产物，不重复生成不同版本。
- 构建错误、资源加载失败、浏览器控制台异常和设备差异在同一结果页展示。
- 临时预览使用短期授权并禁止搜索引擎收录，避免未发布作品被公开发现。

退出条件：

- 一次构建可以在参考桌面与真实手机浏览器完成核心循环，且二者的构建 ID 一致。
- 预览通过后可以直接发布该构建；发布失败时稳定网址仍指向上一个健康版本。
- 导出的开源包离开工作台后仍可由标准静态服务器独立启动。

预计规模：中，约 1–2 周。

### M7：AI 修改后的即时可视验证

产物：

- 每次 AI 修改形成独立变更集，说明修改目标、受影响规则、场景对象、资源和设备。
- 自动生成修改前后预览，并执行构建冒烟、资源完整性、受影响规则和关键视口检查。
- 工作台以“生成中、构建中、验证中、需要复核、已完成、失败”呈现真实状态。
- 失败时显示具体对象和恢复动作，支持整组撤销到上一个健康构建。
- 只重跑受影响检查，但规格、代码或资源哈希变化后绝不复用过期证据。

退出条件：

- AI 说“已经修改”不能直接结束任务；只有预览可打开且受影响 P0/P1 检查通过，工作台才显示完成。
- 故意制造角色过大、移动端遮挡、资源丢失或碰撞错位时，当前变更集稳定失败且可一键回滚。
- 用户能从同一页面看见改了什么、实际画面、哪些检查通过以及哪些仍需人工试玩。

预计规模：中，约 1–2 周。

四项能力的详细边界、数据对象和分阶段顺序见 [创作闭环能力计划](06-creation-loop-capability-plan.md)。

### M8：游戏感与人工体验门槛

产物：

- 每款游戏声明 1–3 个爽点及其可观察信号。
- 增加输入延迟、碰撞余量、预警窗口、反馈层次和恢复成本检查。
- 人工体验复核表覆盖理解、选择、技巧、风险、公平和重试意愿。
- 实验作品在人工确认前保持实验标记。

退出条件：

- 自动检查能发现“赛车太大无法躲避”“背景不动没有速度感”一类结构问题。
- 人工复核结论与具体规则、截图和状态证据关联。

预计规模：中，约 1–2 周。

### M9：浏览器、性能和无障碍补齐

产物：

- Chromium、WebKit、Firefox 发布矩阵。
- 手机横屏、DPR、页面失焦、减少动态、音频恢复和安全区检查。
- 2D/3D 首屏资源、帧率、长任务和内存预算。
- Canvas 游戏提供可读状态和等价操作方式。

退出条件：

- 参考手机和桌面都能稳定完成一局。
- 浏览器差异、资源错误、触控遮挡和焦点问题在发布前可确定性发现。

预计规模：中，约 1–2 周。

### M10：匿名玩法质量数据

产物：

- 单局时长、失败原因、重试、提示、撤销、机制使用和性能事件。
- 项目、版本、规则和随机种子关联。
- 聚合质量看板，不保存自由文本和私人内容。

退出条件：

- 能回答玩家在哪一关、因为什么失败，以及哪项机制没有被使用。
- 数据事件不会影响游戏主循环，也不会泄露用户内容。

预计规模：中，约 1 周。

## 4. P2：能力扩展

只有 P0 和 P1 稳定后才扩展新品类：

1. 轻量经营与队列能力包。
2. 短篇互动叙事与章节能力包。
3. 更完整的卡牌、构筑和事件系统。
4. 单人游戏的手柄等价输入、断开提示和键盘回退。
5. 更复杂的 3D 动画、敌人 AI 和空间谜题。

本地双人、实时多人、可信竞技排行榜和原生平台包不进入本轮路线图；这是“AI 单人网页小游戏制作平台”的产品边界。

## 5. 黄金游戏矩阵

黄金游戏不是商品模板，而是能力回归试卷。第二阶段至少维护：

| 黄金游戏 | 证明能力 |
| --- | --- |
| 俄罗斯方块或 2048 | 确定性状态、时序、计分、撤销和无效输入 |
| 拼图或华容道 | 直接操作、空间合法性、可解性和提示 |
| 虫虫攀枝 | 连续移动、碰撞、程序生成公平、速度感和手机触控 |
| 太空射击 | 多实体、弹体、命中、波次、主动能力和性能 |
| 肉鸽麻将 | 长局恢复、种子、路线、资源选择和差异结局 |
| 区域逻辑 | 唯一解、推理轨迹、解释型提示和零猜测 |
| 3D 收集撤离 | 相机、角色控制、碰撞、检查点和性能降级 |
| 树屋订单 | 截止时间、单工位容量、队列排序和交付结算 |
| 雨夜来信 | 章节状态、关系变量、分支选择和差异结局 |
| 林地卡组 | 固定牌库、能量、连携、敌方意图和回合失败 |
| 三线冲刺 | 手柄轮询、连接状态、断开提示和键盘/触控回退 |
| 旋转机关室 | WebGL 场景、观察角度、空间线索、机关顺序和错误复位 |

新增平台能力必须先在至少一款黄金游戏中通过专属测试，再进入公开能力目录。

## 6. 首批工程任务清单

按执行顺序排列：

1. 新建 `game-spec-v2` Schema 和类型定义。
2. 增加 v1 → v2 迁移器与往返测试。
3. 把进度结构拆为六种模式。
4. 新建规则、动作、不变量和验收证据数据表或 JSON 结构。
5. 修改构建完成逻辑，按验收 ID 更新状态。
6. 给报告增加规格、代码、资源哈希。
7. 引入 `GameProbe` 接口和能力注册表。
8. 先为“虫虫攀枝”实现完整专属探针，作为 AI 原创游戏样板。
9. 为俄罗斯方块、肉鸽麻将和 3D 收集迁移规则合同。
10. 增加规则故障注入测试，证明每个门禁真的会失败。
11. 更新工作台，用普通语言展示规则证据和过期状态。
12. 为每个成熟模板建立固定改造建议、核心锁定规则和越界示例。
13. 建立同类游戏研究服务：优先检索内部机制，再读取官方规则和许可明确的开源实现。
14. 新游戏生成前保存参考档案、采用/拒绝决策和不可复制边界。
15. 完成后再迁移其余成熟模板。
16. 新增 AI 资源生成记录、资源版本和场景引用图，先接入现有角色与背景替换流程。
17. 实现资源加工与打包收集器，确保正式包只包含当前引用的本地位图。
18. 建立跨 DOM、Canvas 和有限 3D 的场景节点适配层。
19. 实现场景画面、层级树和安全属性面板的统一选中与修改。
20. 建立不可变预览构建，并让桌面、手机预览、发布和导出复用同一产物。
21. 为真实手机浏览器提供短期预览链接或二维码，并接入参考视口检查。
22. 建立 AI 变更集与影响分析，自动重跑受影响规则、资源和视口验收。
23. 验证失败时回滚整个变更集，不保留半完成资源或过期证据。

## 7. 阶段完成定义

二次规划的 P0 完成，不以“新 Schema 已写完”为标准，而以以下结果为准：

- 平台对支持范围给出诚实结论。
- 每条 P0 规则都有独立、当前且不可伪造的证据。
- AI 原创游戏必须通过真实玩法路径，而不是只切换胜负状态。
- 修改规则、代码或资源后，旧证据会正确失效。
- “虫虫攀枝”作为首个 AI 原创黄金游戏，能够自动发现此前出现过的空间、速度、碰撞、移动和角色分层问题。
- 全部现有成熟模板仍通过回归检查。

达到这些条件后，平台才进入下一批新品类扩展。
