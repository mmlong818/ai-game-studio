# mkgame-poly 接入审查

核验日期：2026-08-27

## 结论

这个项目适合成为“多格拼块”玩法模板的工程参考，但不能整仓复制，也不能直接把它的关卡和视听资产交付给用户。

平台接入应采用“架构适配 + 原创内容重制”：保留可证明属于 MIT 代码的规则思想和测试方法，重新设计拼块集合、关卡生成器、已知解、名称、位图图集、音乐、音效和界面。它不是通用游戏生成器内核；它是一个完成度较高的单一益智游戏参考。

## 它真正值得借鉴的部分

- 纯状态玩法内核：游戏状态、可用拼块、朝向、落点和胜负判断相互分离，便于自动测试和后续生成关卡。
- 放置规则完整：明确区分越界、重叠、落在目标外和拼块不可用等失败原因。
- 移动端操作成熟：点击任意占用格放置、拖动时寻找最近合法落点、轻微偏差吸附，比只按左上角坐标放置更适合手指操作。
- 关卡编译思路清楚：把原始格子描述统一编译成目标格、允许拼块和已知解，运行时不再理解上游数据格式。
- 难度与进度不是装饰标签：计时、提示次数、星级、Boss 评分、分段解锁都落在真实规则中。
- 验证方法可靠：玩法引擎、关卡编译、计分和解锁均有独立单元测试，核心规则无需依赖页面截图验证。

## 不能进入本平台的内容

上游的 MIT 许可证只覆盖作者独立编写的源代码。上游的第三方声明明确排除了从原 Android APK 提取或改编的内容，包括：

- `public/game/assets/apk-1.0.11/` 下的图像、音乐和音效；
- `resources/apk-1.0.11/lua/` 下的拼块、章节、Boss 和关卡原始数据；
- `src/game/generated/` 下的 1,010 个关卡、已知解及派生数据；
- 原应用图标以及由原 APK 资产衍生的界面素材。

因此，本平台不得复制原版 1,010 关、16 种拼块数据、已知解、地图、美术或声音，也不应使用“原版完整复刻”作为宣传点。完整边界以 [上游第三方资产声明](https://github.com/MkThingsHQ/mkgame-poly/blob/main/THIRD_PARTY_NOTICES.md) 为准。

## 与我们平台的差距

| 项目 | mkgame-poly | 我们的交付要求 |
| --- | --- | --- |
| 产品范围 | 单一 8×8 拼块游戏 | 可生成多种 2D / 3D 小游戏 |
| 数据存储 | 浏览器本地存储 | Docker SQL、项目版本、制作记录和发布记录 |
| 服务器 | 无状态 Cloudflare Worker | 构建任务、资产归档、发布和独立网址 |
| 内容来源 | 固定的原 APK 数据 | 可追踪的原创规则、原创关卡与 AI 位图/声音资产 |
| 交付 | 单个 PWA | 游戏列表、项目页、版本页和稳定游戏网址 |
| 生成能力 | 没有通用生成器 | 玩法合同驱动的代码、资产、测试和交付流水线 |

这意味着不能把上游的 React 页面搬进现有工作台。正确做法是把可复用的规则能力包装成平台现有的独立运行时，由我们的玩法合同、构建记录、资产清单和发布系统管理。

## 推荐的原创模板定义

模板暂定名：`polyomino-fit` / “软糖拼岛”。

- 核心循环：观察目标轮廓 → 旋转并拖动拼块 → 吸附合法落点 → 填满目标。
- 原创内容：平台自有拼块集合和关卡生成器；每关保存生成种子与可验证解，不保存上游关卡。
- 难度参数：棋盘尺寸、拼块数量、可旋转方向、目标空洞率、相似拼块比例、吸附距离、提示次数和计时压力。
- 手机交互：9:16 全屏；目标位于视觉中心；拼块盘分布在外围；支持拖动、点击、旋转、撤销和提示。
- 美术交付：gpt-image-2 生成独立位图拼块材质、关卡背景、封面和反馈特效；声音与音乐单独生成并记录来源。
- 进度设计：原创章节、星级与挑战关；发布后走平台数据库和独立网址，不依赖浏览器本地存储作为唯一事实来源。

## 接入前的硬性验收

1. 代码归属文件只声明实际适配的 MIT 源码结构，不把第三方 APK 资产误标为 MIT。
2. 仓库内不得出现上游受限目录、1,010 关数据、原拼块表、已知解或原媒体文件。
3. 原创关卡生成器必须能用同一求解器批量验证每关有解，并能重建生成结果。
4. 触控测试必须覆盖拖动偏差、最近合法落点、旋转后吸附、撤销和误触恢复。
5. 难度选择必须改变真实规则参数；不允许只改变“轻松/标准/挑战”文字。
6. 游戏必须通过平台既有的位图资产、声音、9:16、可玩探针、项目归档、版本和发布网址检查。
