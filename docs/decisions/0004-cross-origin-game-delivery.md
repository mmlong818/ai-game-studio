# ADR-0004：游戏交付走独立源(端口/子域),iframe 试玩真实跨源隔离

状态：已接受,已实现。  
日期：2026-08-28。

## 背景

审计发现工作台预览 iframe 使用 `sandbox="allow-scripts allow-same-origin"` 且游戏与工作台同源——两个属性叠加等于没有沙箱,游戏代码可以触碰工作台的存储与 API。在引入"模型直接生成玩法代码"(ADR-0005)之前,这条边界必须先立起来。

## 决策

- 服务进程同时监听两个端口:工作台/API(`PORT`,默认 4312)与游戏交付源(`GAME_PORT`,默认 4313;生产用 `PUBLIC_GAME_ORIGIN` 指向独立子域)。
- 游戏端口只承载游戏产物(/play、/version)、模板美术与玩家遥测(POST /api/play-events),不暴露任何工作台 API 与页面。
- 封面、稳定网址、版本网址、预览地址全部由 `StudioRepository` 按游戏源生成;iframe 因跨源而获得真实隔离,`allow-same-origin` 只授予游戏自身源(存档与遥测需要)。
- 生成代码的存档统一走注入的 `safeStorage` 垫片,遥测统一走注入的平台脚本。

## 结果

正面:生成代码即使恶意也接触不到工作台身份与 API;单进程双端口在本地与单机部署零额外成本;生产切换子域只改环境变量。
代价:生产需要两个域名与两份 TLS;本地调试要记住游戏地址在 4313。

## 不采用的方案

- 仅收紧 sandbox 属性(去掉 allow-same-origin):游戏的 localStorage 存档与遥测会全部失效。
- 每游戏独立子域:本阶段运维成本过高,留给对象存储+CDN 阶段(ADR-0003)。
