# ADR-0005：无模板玩法走实验通道,由模型生成独有代码

状态：已接受,已实现并有留存作品验证。  
日期：2026-08-28。

## 背景

一句话创建此前只能命中 14 个模板之一,命中不了就 422 拒绝。塔防、卡牌、经营等玩法被挡在门外;平台的长期目标是开放式创作,不是模板市场。跨源隔离(ADR-0004)就位后,动态代码的安全前提成立。

## 决策

- `gameTemplateSchema` 新增 `generated`:不进模板目录、不参与匹配;LLM 判定无模板可承载时,项目自动进入实验通道并在确认面板标注"实验性作品"。
- 设计合同对 generated 放开规则基线:合同即规则唯一依据,必须具体到能照着写代码。
- 构建时由文本模型生成单文件 HTML,必须满足平台运行时契约:`data-game-state` 状态机、`game:state-change` 遥测事件、`#start`/`#restart` 控件、`?probe=1` 门禁的胜负探针。
- 三道验收:静态安全扫描(禁网络/外链/eval/存储偷渡,违规喂回重试,三轮不过构建失败)→ 真实浏览器契约验收(完整状态环+三档画幅,失败喂回再生成一轮)→ 规则正确性审计(LLM 对照合同逐条核对代码,未实现喂回一轮,最终判定写 RULE_FIDELITY.json,如实记录不拦截)。
- 重建走迭代模式:以上一版代码为修改基础,只落实对话意见与验收反馈,不整局重写。
- 平台脚本(存档垫片+遥测)以哨兵注入,复扫只扫生成段;产物溯源写 GENERATED_CODE.json(模型、轮数、SHA-256)。

## 结果

正面:一句话可以得到模板外的全新玩法(首个留存作品:塔防《茶馆保卫战》,1 轮生成,规则审计 8/8);拒绝路径只剩"设计合同也生成失败"这一种。
代价:构建时长从 ~1 分钟升到 3–7 分钟;规则深度仍以真人试玩为准;实验作品的质量方差大于模板作品。

## 不采用的方案

- 继续 422 拒绝:与产品愿景冲突。
- 生成代码复用模板探针:模板探针绑定具体玩法函数名,对生成代码全部失效,故另立契约级探针。
- 无验收直接交付:违背"真实试玩证据"的平台底线。
