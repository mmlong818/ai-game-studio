# 审核历史后端链路

2026-09-07

## 本批实现

- 新增 version_art_reviews 表。每次人工审核追加版本绑定的历史，保存顺序、前一状态、新结论、原始依据和时间。
- 历史追加、版本当前审核状态、规格内视觉检查状态在同一事务提交，任一步失败全部回滚。
- PostgreSQL 按版本行锁串行化复核，防止历史序号冲突；SQLite 测试事务验证基础行为。
- GET /api/projects/:projectId/versions/:versionId/art-review 只读返回历史，版本不属于项目则拒绝。
- 来源标记 manual-unverified，不能误认为已认证审核员。没有新增篡改历史的应用接口。

## 历史与安全边界

旧版只保留末次审核结果，不能还原已经被覆盖的依据，所以不伪造回填。新历史从本次升级后的复核开始。历史随项目明确删除而级联删除，不是不可篡改存证系统；数据库管理员仍有修改能力。现有身份验证策略未升级，不宣称具有审核员角色隔离。

本批没有增加前端历史时间线，当前可由只读 API 查询；也没有自动审核、重发制作、自动撤下游戏或自动发布。

## 验证

类型检查通过。五项服务端专项测试通过：复核追加历史、版本隔离、失败结论阻止发布、状态更新失败时历史回滚，以及现有封面交付和制作去重测试。测试使用内存 SQLite，不调用模型、不修改真实项目。
