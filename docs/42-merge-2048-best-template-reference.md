# 《数织矩阵》最佳模板参照与重构合同

更新日期：2026-08-30

## 结论

当前 v30 已具备 4×4 棋盘、同值合并、随机生成、一步撤销、历史最佳、危险提示和 20 关入口，基础规则可以运行；但 20 关只把“小目标合成、空间保留、连锁规划、高阶目标”循环五次，局内只提高目标数字和 4 的概率。玩家没有独立开局、任务约束、连锁目标、余白目标、角落策略、下一块信息或收官变化。方块移动后直接出现在终点格，只有生成描边和合并闪光，没有连续位移、汇聚、数字升级和棋盘震动层次。手机版还在棋盘下重复显示四个方向按钮，挤占本应由直接滑动使用的空间。

本轮以 Gabriele Cirulli 的 MIT 版 2048 为规则基线，学习 Threes! 的信息设计与数字角色感，并用 Apple 的游戏触控规范和 Refero 的成熟移动谜题界面约束呈现。不会复制 Threes! 的 1+2 合并规则、角色、美术、音乐、文本或品牌识别。

## 外部参照锁定

### 规则主参照：2048 官方开源版

- 来源：[Gabriele Cirulli / 2048](https://github.com/gabrielecirulli/2048)、[game_manager.js](https://github.com/gabrielecirulli/2048/blob/master/js/game_manager.js)、[官方 App Store 版本](https://apps.apple.com/us/app/2048-by-gabriele-cirulli/id868076805)
- MIT 源码确认：初始生成两块；空位中随机生成 2 或 4，概率为 90% / 10%；只有棋盘发生移动或合并时才生成新块；每块在一次移动中最多参与一次合并；达到 2048 后可选择继续；棋盘、分数和最佳成绩会保存。
- 官方应用页面明确提供：全屏任意位置滑动、一步撤销、统计、个人最佳、声音开关、经典与限时玩法，以及到达 2048 后继续挑战更高数值。
- 本模板采用：标准档保留 90% / 10% 生成分布、合法移动才生成、单回合单次合并、精确计分、一步状态快照、可继续模式和局中自动保存；关卡任务在这套规则之上增加目标，不改变基础数学。

### 策略信息与人格参照：Threes!

- 来源：[Threes! 官方 App Store 页面](https://apps.apple.com/us/app/threes/id779157948)
- 官方页面将其描述为一个简单模式下的无限挑战，强调思考而非快速乱滑；角色插画、音乐和数字人格共同构成完整体验。
- 本模板采用：提前公开“下一块的数值”但不公开随机落点，让玩家可以规划而不消除不确定性；数字块按等级拥有统一材质家族和声音音阶；高阶数字出现时才升级光效，不把每个格子都做成高饱和装饰。
- 明确拒绝：复制 1 与 2 合成 3、单格位移、原作人物、对白、配色、音效或计分。

### 移动端交互参照：Apple 游戏设计规范

- 来源：[Designing for games](https://developer.apple.com/design/human-interface-guidelines/designing-for-games)、[Game controls](https://developer.apple.com/design/human-interface-guidelines/game-controls)
- Apple 建议 iPhone 游戏优先使用触控的直接交互，只有动作多或需要持续移动时才叠加虚拟控制；常用触控目标至少 44×44pt，并提供可见按压反馈，避免虚拟控件遮挡游戏内容。
- 本模板采用：手机在棋盘任意位置滑动；游戏中不再显示四个方向按钮；只保留“撤销”和“返回”两个次要动作；桌面继续支持方向键 / WASD 和 Z 撤销。

## Refero 研究摘要

本轮使用 5 组 iOS 检索，查看了 50 个结果，并深读 8 个代表屏幕：OKURI 滑动教学、Apple News Crossword 棋盘与进行中状态、Brilliant 谜题入口与进度统计、Duolingo 单成果结算、(Not Boring) Habits 里程碑结算等。

可直接采用的设计事实：

| 来源 | 页面公开的具体做法 | 用于本模板 |
| --- | --- | --- |
| OKURI | 全屏教学无卡片堆叠，只用一个大幅手势图、短说明和底部 `SWIPE` 提示 | 首局只显示一次四向滑动示意，完成有效滑动后消失 |
| Apple News Crossword | 棋盘居中占主要面积；当前状态与上下文贴近棋盘；返回和次要操作靠边 | 最高数字、分数、下一块紧贴棋盘上缘，返回与撤销不覆盖格子 |
| Apple News Crossword Archive | 进行中状态、难度和进度集中显示；历史内容与当前谜题分层 | 启动页显示关卡目标、任务类型与上次保存状态，不把统计常驻局内 |
| Brilliant | 当前进度使用少量高对比状态色，统计与主谜题区域明确分开 | 只用一种青绿强调合法增长，一种暖色提示锁死风险 |
| Duolingo | 完成画面只突出一个成果和一个大主动作 | 结算突出新最高数字 / 星章，主动作是下一关，次动作才是继续无尽或重试 |
| (Not Boring) Habits | 黑色舞台、单个金色奖杯、强标题和轻量“继续”提示 | 最终章用克制金属光与数字核心，不做满屏彩带和多卡片统计 |

研究缺口：Refero 没有可核对的 Threes! 或 2048 完整局内录屏，因此具体滑动时间、缓动曲线和声音音阶不从截图反推；这些参数采用本项目真实试玩后校准，并标为本项目实现。

## 参照锁与拒绝项

保留：4×4 经典棋盘、同值合并、方向滑动、一次移动只合并一次、生成 2 / 4、分数与最高数、历史最佳、项目原创“数织矩阵”题材和位图资产。

借用：2048 的精确规则和存档、Threes! 的下一块预告与数字人格、Apple 的直接触控和 44pt 下限、Refero 的一次性教学、棋盘优先层级和单成果结算。

拒绝：把障碍、炸弹、广告复活或随机道具塞进经典模式；用提高 4 的概率冒充全部难度；20 关复用四个名字；方向按钮与滑动并存挤占手机空间；数字依赖颜色才能识别；位图被拉伸到正方形；移动后瞬移；达到目标后强制中止且不能继续；撤销没有次数与状态反馈。

## 完整玩法合同

### 单局状态

`任务简报 → 两块 / 指定开局 → 观察下一块 → 滑动 → 连续位移 → 合并升级 → 新块落位 → 任务检查 → 继续规划`

结算分支：

- 达成目标：`成果定格 → 星章结算 → 下一关 / 继续无尽 / 重试技巧`。
- 棋盘锁死：`锁死格短脉冲 → 最高数字与策略诊断 → 撤销（有次数）/ 重试`。
- 中途返回：保存完整棋盘、分数、下一块、移动数、撤销数和关卡编号，重新进入可继续。

### 核心数学规则

1. 标准棋盘固定为 4×4，初始出现两块；指定挑战关可使用可追溯的预置开局，但之后回到相同生成规则。
2. 标准档下一块为 2 的概率 90%，为 4 的概率 10%；舒缓档 95% / 5%，挑战档 82% / 18%。
3. 只有滑动造成至少一块移动或合并时才消耗回合并生成下一块；无效滑动不生成、不扣步数、不覆盖撤销快照。
4. 同值相邻块沿滑动方向汇聚并翻倍；新合成块本回合不能再次合并。
5. 每次合并把新数字加入分数；多个合并同一回合分别计分，形成连锁数。
6. 满盘且四向均无移动 / 合并时失败；达到关卡目标先进入完成态，玩家可按合同继续无尽。

### 五章二十关

| 章 | 关卡 | 独立目标 |
| --- | --- | --- |
| 初织层 | 成双启程、角落锚点、余白四格、六十四结点 | 学会有效滑动、把最高块留在角落、完成时保留空位、达到 64 |
| 连锁坊 | 双并同拍、三段回声、高低分流、百二十八核 | 单回合两组合并、连续三回合发生合并、保持单调边、达到 128 |
| 预兆廊 | 下一块·二、下一块·四、预兆转向、二百五十六门 | 使用下一块预告安排落点、控制 4、改变堆叠方向、达到 256 |
| 压缩庭 | 密阵开局、一步回溯、限步织造、五百一十二塔 | 不对称密集开局、有限撤销、移动数约束、达到 512 |
| 无尽核 | 千位角锚、零撤销局、连锁三响、二〇四八核心 | 达到 1024、无撤销完成、单回合三组合并、达到 2048 并开放继续 |

每关配置独立的开局种子 / 预置格、目标数、任务类型、任务阈值、移动上限、撤销次数和下一块序列。四关一章增加一种可学习的压力，下一章首关允许降低目标数但引入新信息，不要求每关机械递增。

### 任务与星章

- 必做：完成本关主任务并达到目标数字。
- 星章一：达到目标数字。
- 星章二：满足本关策略条件，例如最高块位于角落、保留至少四个空位或完成指定连锁。
- 星章三：在建议移动数内完成，或全程不使用撤销。

任务条件必须在启动页说明，局内只显示短标签和实时进度。玩家不能因为已经达到数字目标却没看到隐藏条件而失败；若主目标已达成，策略条件只影响星章。

### 移动、合并与生成表现

- 方块在 140–180ms 内沿真实格路径移动，统一使用 ease-out；不是先擦除再在终点重画。
- 同一回合的两块先移动到共同格，再以 90–140ms 的压缩—回弹显示新数字；合并音高随数字等级上升但限制峰值音量。
- 新块只在移动完成后以 110–150ms 缩放出现；下一块预告在生成后立即更新。
- 无效滑动只提供棋盘边缘 3–5px 的阻尼回弹和低音，不生成新块。
- 临近锁死以空位数、可合并对数量和暖色边缘共同提示，不用覆盖棋盘的大弹窗。
- 支持 `prefers-reduced-motion`：保留状态变化但缩短位移和弹性，不闪烁。

### 视觉与声音

- 视觉主题采用当代织物 / 珐琅数字块：背景低频、棋盘中性、数字块按等级从冷玉到暖金渐进；数字始终是第一识别层。
- 每个等级块使用同一位图材质家族，不能把不同比例插画强塞进正方形；位图只作为底面与边缘纹理，数字用高对比实时文字保持清晰。
- 空格、2–16、32–128、256–512、1024+ 至少形成五级明度和边缘差异；除颜色外还用边框层数、纹理密度和数字字重区分。
- 音乐保持低干扰循环；移动、无效、生成、普通合并、连锁、危险、达标和锁死使用可区分的短反馈。

### 屏幕与输入

- 手机 390×844：棋盘宽度占可用宽度 88%–94%，局内尽量垂直居中；顶部只显示目标、最高块、分数、下一块和移动数；底部不放四个方向键。
- 手机在棋盘任意位置滑动，阈值 18–28px；一次 pointer 只提交一个方向；取消、离开和多指输入不能残留手势状态。
- 撤销按钮至少 44×44px，明确显示剩余次数；无次数时禁用而非点击后无反应。
- 桌面使用方向键 / WASD；Z 撤销；R 重开前给出可恢复确认或只在结算态直接重开。
- 游戏页只允许返回和撤销，不显示难度、声音、关卡选择或长帮助；这些位于启动页。

## 自动验收合同

- 20 个关卡名称、蓝图和开局签名唯一；五章目标与任务类型真实变化。
- 对 `[2,2,2,2]` 左滑得到 `[4,4,0,0]`，不能得到 `[8,0,0,0]`；无效滑动不生成；一次合法滑动只生成一块。
- 标准档大量确定性抽样的 2 / 4 分布接近 90% / 10%，并可通过固定随机种子复现。
- 下一块预告值与实际生成值一致；随机位置只从空格选择。
- 位移动画、合并动画和生成动画按顺序完成；快速连续输入被排队或拒绝，不会在动画中写坏棋盘。
- 撤销完整恢复棋盘、分数、最高数、下一块、移动数与随机状态，并消耗一次额度。
- 自动完成至少三种任务，触发一次锁死和一次无效滑动；保存后重载状态一致。
- 手机直接滑动和桌面键盘结果一致；390×844 没有方向键挤占棋盘，文字与数字不被背景吞没。

## 放行条件

- 20 关不再依靠目标数字单一增压，至少包含角落、余白、连锁、预告、限步、撤销和无撤销七类策略条件。
- 棋盘、数字、目标、下一块、危险和操作形成稳定层级；宣传图使用的块面质量必须在局内真实出现。
- 手机和桌面各完成 3 局并触发 2 次失败 / 锁死；持续快速输入不产生双步、漏步或未处理错误。
- 18/18 构建验收、阶段 D 专项浏览器验收和主美复核全部通过后，才发布稳定网址。
