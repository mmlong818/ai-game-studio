# 产品改造第二阶段：试玩与修改工作空间

日期：2026-09-07

## 已落地

- 将修改意见、确认和制作新版连为一个流程，不再要求用户先发消息再找构建按钮。
- 试玩保持主要位置，方案、制作、审核记录默认折叠；收起记录不代表删除质量检查。
- 修改先显示确认内容与模型用量提示，返回修改保留草稿，明确确认后才请求制作。
- 使用请求 UUID 将修改意见和构建记录原子保存；相同请求返回同一任务，终态也不重建。活动任务存在时拒绝另一修改。
- 客户端先持久化请求收据，刷新只查询恢复，不自动 POST；显式再次确认仍沿用原请求 ID。
- 保持上一阶段的成功版本预览，不在新构建失败时覆盖可玩版本。
- 手机顶部按钮避免中文断行，修改表单支持窄屏。

## 验证

- TypeScript 前后端类型检查通过。
- 前端 81 个测试文件、356 项测试通过，包含确认前不提交、双击保护、草稿恢复和响应丢失后的只读恢复。
- 服务端专项 8 项测试通过；其中修改任务测试使用真实内存 SQLite 事务验证重复请求和写入失败回滚，没有调用模型。
- 独立真实浏览器验证已有游戏预览、填写修改、查看确认、返回修改和 390px 布局；未点击实际付费制作确认。
- 后端在现有项目无活动任务时重启，新 revisions 查询接口返回正常。没有自动重试历史失败任务。

## 边界与后续

这不是整个应用改造完成：全站视觉统一、模型设置面板、人工审核责任与预算上限仍需后续推进。本阶段未验证远端模型实际生成新版；不将自动化测试通过描述为游戏品质全面达标。

请求去重作用于同一 requestId；客户端遗失本地收据或跨设备独立提交不等于同一请求。后续已补充数据库级项目锁和构建执行权领取，见 [制作数据库边界](89-build-database-claim.md)。创建队列与重启恢复仍未完成多实例治理，尚不能部署多个 API 实例。
