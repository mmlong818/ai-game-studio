# 生成验收服从确认方案：有限关卡与无失败规则

2026-09-07。整体改造仍在进行，本记录不是六个工作包的完成声明。

## 已实现

新生成方案可携带 `generatedCampaign`：总关数、结构变化关、真实数值维度、失败策略和策划依据。策划服务校验结构；方案页直接显示关数与是否会失败，确认提交时保留全部数据。项目规格、生成指令、产物清单、静态检查和浏览器检查共用该计划。

制作流程把数据库中的确认计划传给两层验收。产物不能自报更少关数、删掉声明或替换维度来降低检查要求。非法结构不回退默认值。规则代码审计也收到关数和参数要求；探针返回值仍不等同于自然操作证明。

有限关卡可为 1–60 关；结构变化关必须从 1 开始、递增且不越界。新计划只检查声明的真实数值维度，不要求虚构速度与密度倍率。超过最后一关的选择必须钳制到末关。教学复演使用不超过总关数的关卡，不再向七关游戏请求第九关。

明确禁止失败的计划不要求 `forceLose`，不注入连续失败帮助。对应帮助报告标记 `not-applicable`，不列入通过项。浏览器通过事件和 DOM 状态观察已测操作中的失败，包括瞬时失败；证据保存在浏览器侧之外，刷新不能抹掉。正常翻牌输入检查也使用这一监测。

官方模板不接收模型返回的生成关卡覆盖。旧产物和没有该字段的旧确认方案仍采用原二十关严格检查，禁止推测免检。

## 验证

- 隔离浏览器七关正例通过，实际可进入第八关的负例被拒绝。
- 无失败且无 `forceLose` 的样本通过；教学操作中瞬时失败后恢复的负例被拒绝。
- 旧二十关样本和 3D 样本继续通过。
- 单元测试覆盖非法结构、单关、项目关数一致性和服务端信任边界。
- 测试使用模拟模型或隔离产物，不调用付费 API、不重新制作现有游戏。

本批最终验证：前端 84 个文件、365 项测试通过；策划／生成／关卡与浏览器专项 42 项测试通过；前后端类型检查通过。浏览器样本是验收框架回归，不是新生成游戏的趣味性认证。

## 未完成边界

无限／无目标玩法、禁止时间压力的独立声明、每关参数范围与幅度、完整合同版本及哈希报告、更多类型的自然输入解法仍需迁移。当前数值监测不证明参数确实影响游戏；失败监测也只覆盖执行过的操作，不能证明所有路径不存在失败。旧兼容设计合同仍有有限旅程和失败帮助描述，新生成指令与实际辅助计划以显式失败策略覆盖；完整合同结构迁移尚未结束。

缺少 `generatedCampaign` 的方案仍走 legacy，不宣称所有历史方案已自动摆脱固定二十关。尚未进行本轮改造后的付费端到端生成验收，也未完成预算恢复、多实例任务治理和全站收口。
