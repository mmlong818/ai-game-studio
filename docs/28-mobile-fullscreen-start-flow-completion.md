# 手机满屏游戏与启动设置流改造

日期：2026-08-27

## 设计目标

为手机上的休闲与轻度 3D 游戏建立统一路径：玩家先在启动页完成关卡、难度、模式、图片和声音选择，进入后尽量只看到游戏、必要状态与操作；任何时候都能返回启动页，但游玩界面不重复提供设置。

记忆点不是“又一个设置面板”，而是进入游戏后界面迅速退场，游戏主体保持 9:16 且占满当前屏幕能够容纳的最大区域。

## 外部研究摘要

研究方式：8 组官方文档检索，重点复核 Apple 游戏设计、触控、安全区、设置与 Android 全屏、边到边和多设备输入规范。当前环境没有可调用的 Refero MCP，因此没有冒充 Refero 屏幕库研究；实现同时使用了本地 `refero-design` 的排版、触控、图标、颜色和防模板化检查基线。

关键事实：

- Apple 建议游戏采用不受干扰的全屏体验，并针对不同画幅使用动态布局，而不是固定压缩。
- Apple 建议高频触控目标至少 44×44 pt，控件要避开安全区和系统特征。
- Apple 建议仅在动作可用时显示对应虚拟控件，尽量减少控件覆盖游戏内容。
- Apple 将设置定位为低频操作；玩家需要中断当前任务才能调整，因此不应持续占据游戏主界面。
- Android 的沉浸模式用于游戏等全屏内容，同时要求系统栏仍可通过系统手势恢复。
- Google Play Games 指南要求不同画幅下 UI 和玩法元素保持可见、可操作，并正确维持或恢复游戏状态。

采用的具体策略：

| 来源 | 策略 | 本项目落地 |
| --- | --- | --- |
| Apple Designing for Games | 全屏、动态适配多画幅 | 9:16 主体按屏幕可容纳尺寸最大化，不拉伸 |
| Apple Game Controls | 44×44 pt 高频触控目标 | 返回、重开、方向与 3D 控制均保持至少 44px |
| Apple Game Controls | 隐藏当前不需要的虚拟控件 | 开局前禁用控制；游玩时隐藏帮助和设置 |
| Apple Safe Area | 避开刘海、圆角与 Home 指示器 | 全部手机浮层使用 `env(safe-area-inset-*)` |
| Apple Settings | 低频设置不持续占据主界面 | 关卡、模式、难度、图片和声音统一移到启动页 |
| Android Immersive Mode | 沉浸内容减少意外退出 | 游玩状态锁定页面滚动，仅保留明确返回按钮 |
| Google Play Games | 状态可恢复、元素不得遮挡输入 | 返回后恢复启动设置；自动探针验证状态与遮挡 |

研究缺口：没有对商业游戏私有界面做像素级复制；本轮只采用平台一手规范和项目已有艺术方向，避免把某款产品的视觉身份搬进本平台。

## 已完成实现

### 通用 2D 模板

- 启动页统一承载 20 关选择、俄罗斯方块模式、拼图图案和数量、贪吃蛇难度、自定义图片与声音。
- 删除游戏侧栏内重复的拼图和贪吃蛇设置。
- 手机游玩时隐藏帮助、制作说明、设置和声音按钮，只保留紧凑状态、必要操作、返回与重开。
- 9:16 画布使用 `min(100vw, 56.25svh)`，在不变形的前提下达到当前视口最大尺寸。
- 启动页在 320×568 上可滚动，游玩页不滚动；控制和返回按钮使用安全区内边距。
- 返回启动页会停止环境声音、退出 `playing` 状态并保留当前已解锁关卡和设置选择。

### 通用信号搜寻模板

- 声音移入启动卡，游玩页只显示战况、返回和重开。
- 返回会停止计时器和环境音、隐藏目标并恢复启动设置页。
- 手机舞台保持最大 9:16，背景延伸到留白区，避免生硬黑边。

### Three.js 3D 模板

- 新增安全区内的返回按钮，游戏中不出现设置。
- 返回时清空方向输入、暂停环境音、退出运行状态并恢复关卡启动卡。
- 结算卡新增“返回设置”，玩家可以在下一局前选择关卡。
- 3D 画布保持最大 9:16，手机控制按钮不小于 44px。

### 《星梦对决》固定三消

- 声音从游戏顶栏移到启动设置卡。
- “新对局”改为明确的“返回”入口，并接入统一 `idle → playing → idle` 状态。
- 手机页改成最大 9:16 舞台；积分状态浮于顶部，棋盘居中，提示位于底部，设置弹层不进入游戏层。

### 自动验收

手机真实浏览器探针现在额外验证：

1. 游戏主体达到保持 9:16 时可用高度的至少 94%。
2. 游玩状态没有纵向滚动。
3. 关卡、模式、难度、图片和声音设置在游玩状态不可见。
4. 返回按钮至少 44×44px。
5. 返回后状态是 `idle`，启动按钮和设置恢复可用。
6. 再次开始后仍能进入 `playing` 并完成胜利、结算和重开探针。

## 验证结果

- TypeScript 类型检查通过。
- Vite 生产构建通过，共转换 1894 个模块。
- 13 个生成器、数据库、发布闸门、归档和 3D 定向测试全部通过。
- 通用 2D 模板已在 320×568、390×844、768×1024、1280×720、1440×900 五档真实 Chrome 画幅通过。
- 390×844 实测游戏主体为 390×693px，等于该屏幕保持 9:16 时可容纳的最大高度；设置只在启动页出现，返回后可重新开始。
- 已人工查看手机启动页与游戏中截图，修正了首版返回按钮被旧 `bottom` 规则拉成长条的问题。

## 当前交付边界

源代码、固定三消、自动验收和生产构建已完成。当前 4312 服务仍是改造前启动的旧进程；由于系统拒绝了本轮沙箱外的服务重启权限，新生成器尚未加载到在线服务，也没有据此重建并切换现有游戏稳定网址。旧版本和数据库没有受到影响。

必须在获得明确的本地服务重启授权后，重启 4312，按发布闸门为现有游戏生成不可变新版本，通过浏览器与主美检查后再切换稳定网址。
