# 图先行链路的首次真实制作与三处修复

2026-09-08。本文记录一次完整的真实制作验证，以及验证暴露的三处缺陷与修复。趣味性仍以真人试玩为准，本轮不宣称已解决。

## 起因

[96](96-knowledge-blueprint-and-art-first.md) 建立了知识蓝图与“资源先于代码”的顺序，但明确写着未做付费端到端复验。本轮补上这次复验：故意提交上一轮被判不合格的那类创意（“点贝壳、每关数量变多、没有失败”），看链路会不会自己拦住它，再走完制作。

## 方案阶段：门禁按设计生效

策划阶段用本机 Claude CLI 生成的方案没有沿用纯点选：竹篮六格、潮水周期、倒回即永久丢弃、第四关同色成对、第五关两个清单槽位争抢同一种贝壳。`coreDecision`／`tension`／`masterySignal` 三项写的是真实取舍，难度递进每关改变决策结构而不是加数量。落库蓝图是库内真实 id：`mechanicIds: [collect-set, risk-push]`、`modifierIds: [scarce-budget, simultaneous-cycle]`，`sprites` 声明 5 个局内主体。

## 缺陷一：蓝图声明的局内主体从未被生成

第一次真实制作在资源步骤必然中断：`确认方案要求的局内主体位图未全部生成`。

`dynamicArtPlan()` 是纯计划，包含蓝图主体；真正发图的 `generateDynamicArt()` 只跑背景、`roleArtPlanFor(template)` 与 `generateSpriteSet(template)`，而 `generated` 模板这两张表都是空的。计划要 7 张，实际只出 2 张，编排器随即按设计中断。也就是说 96 那次改造对每一个生成游戏都是必然失败。

`tests/image-generator.test.ts` 里“局内主体进入图片计划”只断言了 `dynamicArtPlan`，没有断言真的发图，因此测试全绿而链路不可用。

修复：蓝图主体收敛为单一事实源 `blueprintSpriteSet(project)`，计划与生成共用；`generateDynamicArt` 按与计划一致的下标顺序真实生成（图像检查点按下标比对计划与产物，顺序不能错）。新增回归测试断言产物与计划逐项一致，且每张都真的调用了生图接口。

## 缺陷二、三：合同没写、验收却强制的两条要求

修复缺陷一后资源步骤通过（7 张图在代码生成之前全部落盘），但两轮代码生成都倒在浏览器验收，两轮的原因都是运行时合同没有写、验收却强制要求的：

- `#start` 必须在 360×640 首屏内完整可见（`top >= 0 && bottom <= innerHeight`），合同第 2 条只写了“至少 44x44px”。
- 结算后必须能直接点到 `#restart`。生成代码把 `#restart` 放在顶栏、结算用全屏遮罩面板——而合同第 2 条恰恰鼓励“使用独立可滚动面板”，没有说面板不能盖住 `#restart`。

2 轮修正预算被两条模型无从得知的隐性要求各消耗一轮，生成游戏基本不可能完成制作。

另外 `browser-quality.ts` 中游戏内那次 `#restart` 点击没有 `.catch`，异常直接冒泡成“验收中断”，修正轮拿到的是 Playwright 原始超时日志而不是可执行判定；同文件结算后那次点击本来就有遮挡诊断。

修复：合同第 2 条补上首屏可见要求，以及“结算面板出现时 `#restart` 必须仍可直接点击——放进面板内部，或让遮罩不拦截其指针事件”；游戏内那次点击改为与结算后一致的诊断式判定。

## 结果

同一方案第三次制作成功。资源步骤 7 张图全部命中图像检查点缓存，未重复生图；代码一轮通过静态与浏览器验收；规则审计 17/17 逐条核对已实现。产物 `app.js` 实际 `drawImage` 绘制 5 张局内主体与局内背景，沙滩上的贝壳、寄居蟹壳与六格竹篮都是 AI 位图而不是 canvas 自绘图形。

未解决、未验证的部分：本轮没有真人试玩，不能断言这次的取舍设计真的好玩；桌面画幅下页面内容偏窄、留白偏多，验收只检查横向溢出，没有覆盖这类观感问题；两轮修正预算对“合同与验收不一致”这类问题仍然脆弱，本轮只补齐了已发现的两条。

## 验证

`npm run typecheck` 通过；`npm run test:platform` 87 文件 397 项通过；`npm run test:legacy` 287 项通过（均为本轮单次运行结果）。真实制作的证据是构建 `28c5d3f1-4f0f-4756-9d17-45e6e8795bae` 的产物与 `_studio/quality` 截图。
