# 第一套可运行工程

日期：2026-08-26。  
状态：第四个可运行切片已实现并通过本地验证。

## 设计简报

这是一个面向不懂代码的中文游戏创作者的制作工作台，帮助用户先把模糊想法变成可检查的玩法合同，再逐步进入构建、试玩、版本和独立网址。界面应像可信、专注、有创作能量的数字工作室，而不是聊天机器人或模板商城。

用户雇用它完成的工作：

> 把我的玩法想法变成一款真的能玩、能修改、能发布到独立网址的游戏。

主要反对意见：AI 游戏只是演示、所有作品只是换皮、修改会破坏旧版本。第一套界面用真实黄金游戏、8 项规则证据、数据库状态和不可变网址回应这些问题。

记忆点是“可玩证据带”：想法 → 合同 → 构建 → 试玩 → 版本 → 网址。

## 已实现范围

- 响应式 React 工作台。
- 一句话中文玩法输入、模板自动识别与 2D/3D 显式选择。
- 八个成熟起点：俄罗斯方块、图片拼图、打砖块、华容道、迷宫、贪吃蛇、数字合成和太空射击。
- 主任务单一的创建入口；经典、沉稳、时尚、软萌、简笔画、色块六种画面风格直接可见，并用结构化缩略图说明布局、构件和细节密度差异；难度、名称和空间形式按需展开。
- 画面风格写入 `game-spec`、硬约束、验收清单、美术方向和资源清单，并同步控制游戏壳层、位图图集选择与 Canvas 合成方式；历史版本缺少字段时兼容为经典风格。
- 经典拼图支持咬合边、自由拖拽和靠近正确位置自动吸附；不是空格换位式滑块拼图。
- 拼图创作时图片上传：浏览器保留横图、竖图或方图的原始比例，按请求大小逐级缩放和压缩并预览；生成后的游戏仍可替换图片，拼块行列与画布随图片比例重新计算。
- 拼图块数提供 6、9、12、16、20、24、30、36、42、48、50 共 11 个可整齐分解行列的档位；开局所有拼块排在中央画板外围。
- 难度规则被写入 `game-spec`：轻松默认 9 块、标准默认 20 块、挑战默认 42 块，并分别调整吸附范围和参考底图透明度；玩家选择可覆盖默认块数但不能超过 50。
- Zod 输入边界和通用 `game-spec`。
- 确定性本地合同生成器，尚未冒充 AI 模型结果。
- Node HTTP API。
- Docker PostgreSQL 18.6 开发数据库及项目、规格、构建、版本、发布表；旧 SQLite 仅作为首次迁移来源。
- 星梦对决黄金夹具的稳定玩家网址和不可变版本网址。
- 独立游戏静态资源服务与安全响应头。
- 合同就绪、可玩、已发布三个真实状态。
- 桌面真实浏览器创建项目与打开游戏路径。
- 构建任务和构建步骤数据库表，记录排队、执行、成功、失败、输出和错误原文。
- MakePlay 式“制作步骤与产出 + 实时试玩”独立双栏制作页；项目使用 `/projects/:id` 专属网址，不使用浮动弹层。
- 2D 构建器：为八类玩法分别写入独立规则脚本、专业游戏设计与三份方向/归属文档、游戏文件、资源清单、生成图像和独立音频。
- 雾港样条的封面与场景图由 `gpt-image-2` 真实生成；两套最终提示词与模型信息随资源归档。
- 20 秒环境音乐、捕获、警告和胜利音效均为独立 WAV；来源明确标记为程序化合成，不冒充 AI 音乐。
- 八套 2048×1152 主视觉和九套 1024×1024 游戏内位图图集由 `gpt-image-2` 高质量模式真实生成；图集经本地色键转为 RGBA，并把最终提示词、模型、尺寸、Alpha 处理和哈希随资源归档。
- 八类 2D 游戏的主要角色、方块、道具和材质从位图图集绘制；纯色几何只保留碰撞、边界和文字可读性所需的程序层，不再冒充正式美术。
- 每套四个真实 WAV：环境声、操作、成功和失败；来源明确标记为程序化合成，不冒充 AI 音乐。
- 每类模板游戏 11 项本地试玩探针，其中位图探针检查图集文件、资产清单和 Canvas 消费路径；通过后生成不可变版本，再切换稳定玩家网址。
- 服务重启会把悬空任务标记为可重试失败，不让页面永久卡在“制作中”。
- 3D 项目会生成本地 Three.js WebGL 2 运行时，包含场景、第三人称移动、跟随相机、碰撞、收集、倒计时、出口结算、触控和 14 项独立探针；环境、地面和遗迹消费位图纹理，角色、碎片与出口使用透明位图精灵。
- `/games` 统一游戏大厅，只读取数据库中已经发布并在线的游戏，集中呈现稳定玩家入口。
- 游戏大厅直接读取稳定玩家网址下的真实封面，图片失败时保留程序化回退画面。
- 八款示范游戏可以通过同一条“合同 → 构建步骤 → 自动探针 → 不可变版本 → 发布”链进入游戏大厅。
- 真实浏览器逐款完成启动与一次操作，桌面画幅均显示 718×718 可玩画布且无控制台错误；手机 390×844 画幅无横向溢出，触控按钮可操作。

## 当前没有实现

- 模型调用与多轮澄清。
- AI 驱动的开放式代码生成、隔离沙箱和自动修复循环。
- PostgreSQL 生产适配器。
- 对象存储、CDN 和公开域名部署。
- 任意类型新游戏的开放式代码生成，以及按每个项目动态规划和生成独有视听资产；当前已验证八类独立 2D 能力包。
- 更复杂的 3D 能力包：骨骼动画、战斗 AI、空间音频、物理引擎和模型资产优化。

这些能力不能在界面中显示为已经完成。

## 视觉决策

- 暖中性纸面背景与墨色正文，橙红只用于主要动作和状态焦点。
- 不使用紫色、泛光渐变或通用 AI 插画。
- 用不对称的“创作表单 + 真实黄金游戏”构图表达产品核心。
- 一套 Lucide 线性图标；按钮和图标均保留可见键盘焦点。
- 手机端从双栏折叠为自然滚动的单列独立页面，不使用固定或悬浮操作区。
- 游戏大厅使用不对称卡片比例区分主推与普通作品，同时保持同一套暖中性、墨色和橙红品牌语言。
- 雾港游戏页使用生成场景本身建立空间层级，UI 只保留墨色信息面与安全橙信号，不用装饰性渐变掩盖图片。
