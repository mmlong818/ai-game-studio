# 无限玩法与安全恢复

2026-09-07，阶段性历史记录。后续真实交付见[91](91-real-creation-closure.md)，审核权限与成功图片检查点见[92](92-production-safety-and-review.md)。本文测试数量和部署状态只代表当时，不代表最新总数。

## 已落地

- 确认计划增加 `mode: campaign | endless`。无限模式总关数为0、结构变化关为空；不要求setLevel、forceWin或第九关复演，不把不适用检查算成通过。
- 浏览器在普通翻牌输入和探针检查中监测禁止的won/lost状态；瞬时事件保存在浏览器页面之外，刷新不能抹掉。无限模式短期观察与长期内容供给验证明确分开。
- 新版API在迁移、目录初始化和中断恢复之前取得数据库会话级运行权。第二个API被拒绝启动，避免把仍在执行的任务误标为中断。当前是安全单主，不是多活或高可用集群。
- 重启只恢复尚未开始的queued创建／构建回执，仍以数据库条件更新领取执行权。creating／running可能已产生模型费用，保留失败结果，不自动重试。
- 代码生成的内部安全修正和外部玩法修复共享每任务3次请求额度，不再乘法叠加。额度是请求上限，不是金额预算，也不包含策划、图片和审核调用。
- 只有明确的产物检查失败才能授权付费修复；缺失浏览器、读盘故障等非产物验收错误停止处理，不直接再生成游戏。
- Windows PowerShell启动健康检查使用UseBasicParsing，避免把已就绪服务误报为启动失败。
