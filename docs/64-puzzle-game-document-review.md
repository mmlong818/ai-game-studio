# 《益智游戏.md》可用内容评审

> 评审对象：用户提供的本地文档《益智游戏.md》  
> 结论：适合作为设计检查清单来源，不适合作为流行趋势、玩法有效性或市场表现证据。

## 可直接结构化采用

- 清晰目标、规则、合法动作和完成状态。
- 每个阶段只教学一个新概念，先安全练习，再加入时间、空间或资源压力。
- 难度循序递进，在挑战之间安排巩固与缓冲。
- 渐进提示、失败原因、检查点、重试与可重看的帮助。
- 键盘、指针、触控的等价操作，以及动作、非法输入、奖励和失败的即时反馈。
- 透明计分、结算摘要、个人最佳与可解释的改进方向。
- 通过目标、空间、信息、资源或机制组合产生结构性复玩变化。
- 不只依赖颜色或声音的无障碍线索。
- 同时记录定量行为与定性反馈的试玩—修改—复测闭环。

以上内容已规范化为 `src/shared/game-design-knowledge/puzzle-guidelines.ts`，每条规则包含采用级别、验收条件、验证方法和适用标签，可被策划整合器和评估器读取。

文档提出的试玩闭环也已转成结构化记录：教学清晰度、操作清晰度、主观难度、趣味、公平性、重玩意愿、提示次数和标准卡点可以进入季度复核；不保存测试者身份和自由文本，从源头减少隐私信息与不可比较的散乱意见。

## 需要改写后采用

- 受众不按年龄、性别或地域刻板推断，改用游戏经验、动机、设备、可用时长和无障碍需求。
- 叙事、世界与角色是可选表达层，只在强化玩法理解或动机时加入，不作为所有益智游戏的硬要求。
- 随机与程序生成必须增加同规则下的变化，同时满足固定种子复现和可解/安全路径验证。
- 提示可以有设计成本，但默认不能使用羞辱文案、强制等待或阻断完成体验的惩罚。

## 不作为默认能力

- 排行榜、社交分享、用户生成内容和赛季活动会引入账号、运营、审核与合规成本，与当前“单人网页、非专业用户最小操作”的范围不一致。
- “独特”“创新”“令人上瘾”等主观表述不能成为验收项，必须改写成可观察的玩家行为与试玩指标。
- 性能优化、资源压缩和加载速度属于引擎与生产管线评估，不重复塞进玩法知识规则。

## 文档本身不能提供的内容

- 没有引用来源、观察日期、玩家样本和市场数据，不能提升玩法模式的证据等级。
- 没有具体游戏样本及机制关系拆解，不能直接扩充玩法库。
- 没有求解器、随机公平性、固定种子、探针事件等自动验证设计。
- 没有资源权利、素材来源和版权边界。

因此，本次吸收的是其中稳定、通用的设计原则；具体玩法、热门程度和参考游戏仍须按研究队列取得外部证据后入库。
