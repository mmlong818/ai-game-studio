# mkgame-sudoku 接入审查

核验日期：2026-08-27  
上游仓库：[MkThingsHQ / mkgame-sudoku](https://github.com/MkThingsHQ/mkgame-sudoku)  
在线版本：[MimoDoku](https://sudoku.mksaas.link/)  
核验提交：`2f8af39a365f328f8420d658cd595b79ecf92d14`

## 结论

这个项目可以成为平台的新逻辑放置模板，但不能按传统数独接入。它的实际规则是：每一行、每一列、每个彩色区域必须恰好放置一只猫，同时任意两只猫不能水平、垂直或对角相邻。它更接近“区域独占/Queens”类逻辑谜题，和填写 1–9 数字的数独不是同一种游戏。

推荐采用“MIT 规则移植 + 原创题目生成器 + 独立美术重制”。玩法状态、输入、提示、撤销、自动标记、唯一解求解和测试方法可进入平台；MimoDoku 品牌、猫咪吉祥物、图标、宣传图和游戏音乐不能使用。

## 对上游题库的实际核验

上游 README 宣传“80 个手工逻辑题”，但代码实际只定义了 6 个基础棋盘，再通过水平翻转、垂直翻转、180 度旋转和区域编号换色扩展为 80 个关卡。

本次另外运行了独立回溯求解器，按“行唯一、列唯一、区域唯一、相邻禁放”四条规则验证上游提交中的全部关卡：

- 80 个关卡均有且只有一个解；
- 没有无解题；
- 没有多解题；
- 80 个关卡实际只有 35 个不同的“区域布局 + 答案”组合，其余是重复变换或换色。

因此，上游题库在逻辑正确性上可以参考，但内容丰富度和“手工题”表述不符合实际代码。我们的平台不能照搬这 80 个编号后继续宣传为 80 个原创关卡，必须使用真正的生成器和去重机制。

## 值得进入平台规则库的能力

### 玩法状态

- 棋盘尺寸支持 5×5、6×6、7×7、8×8 递进；
- 每行、每列、每区域恰好一个目标；
- 相邻八方向禁放；
- 点击空格可放置目标，也可先标记排除格；
- 正确放置后自动标记同一行、列、区域和相邻格；
- 错误放置消耗失误次数，并给出明确反馈；
- 撤销、有限提示、失败、完成和下一关构成完整局内流程。

### 生成与验证

- 题目必须保存区域地图和唯一答案；
- 每个候选题必须由独立求解器计数，只有解数量恰好为 1 才能发布；
- 每日题应由日期和版本生成稳定种子，同一天、同一版本得到相同题目；
- 关卡哈希用于去重，旋转、镜像和纯换色后的同构题不能冒充新关卡；
- 难度应由求解步骤、候选分支、棋盘尺寸和提示依赖度决定，而不是仅按关卡编号递增。

### 真实使用体验

- 首次进入必须演示“每行/列/区域一个”和“猫不能相邻”两类规则；
- 自动标记、声音、触觉和减少动态效果均可独立开关；
- 刷新后恢复棋盘、提示数、失误数和计时；
- 离开未完成游戏前给出确认，避免手机返回手势误丢进度；
- 小屏必须保证整张棋盘可见，控制按钮不能挤压或覆盖棋盘。

## 不能进入本平台的内容

上游 [第三方资产声明](https://github.com/MkThingsHQ/mkgame-sudoku/blob/main/THIRD_PARTY_NOTICES.md) 给出了以下边界：

- MimoDoku 吉祥物、应用图标和 Open Graph 宣传图只作为 MimoDoku 项目资产提供，不能当作通用 MIT 素材使用；
- `public/audio/mimodoku-gameplay-loop.ogg` 来源于公开可获取的应用资产，只供学习和研究，不能复制或再分发；
- 自托管 Bricolage Grotesque 字体使用 SIL Open Font License，Tabler 图标使用 MIT；即使许可明确，平台也没有必要为了单个模板重复引入字体和图标依赖。

平台需要独立生成角色、棋盘区域纹理、封面、图标、完成动画、音乐和音效。不能沿用“MimoDoku”名称、字标或原猫咪造型。

## 推荐的原创模板定义

模板暂定名：`region-logic` / “星灵巡格”。

- 核心循环：观察区域 → 标记不可能格 → 放置星灵 → 自动排除同行、同列、同区域和相邻格 → 完成唯一布局。
- 题材可变：猫咪、星灵、花朵、灯塔、宝石、露营帐篷等都只是表现层；规则层保持可测试。
- 难度参数：棋盘尺寸、区域形状复杂度、初始提示格、允许失误次数、提示次数、自动标记范围和目标解题时间。
- 美术要求：每种风格改变角色造型、区域边界语言、格子纹理、标记符号、反馈动画和细节密度，不能只改变区域颜色。
- 手机布局：默认 9:16，棋盘是画面主体；状态和操作按钮放在上下安全区，教程、帮助和完成弹层不能遮挡正在推理的棋盘。
- 数据交付：题目种子、生成器版本、唯一解证明、当前局面、提示/失误、用时、星级和每日完成记录写入平台 SQL，并随独立网址发布。

## 接入前的硬性验收

1. 不复制 MimoDoku 吉祥物、图标、宣传图和 `mimodoku-gameplay-loop.ogg`。
2. 每个生成题必须由求解器验证“解数量等于 1”，不能只验证预设答案满足规则。
3. 关卡去重必须识别旋转、镜像、区域换色等同构变化。
4. 难度必须由求解复杂度或可解释指标驱动，不能只靠棋盘变大和关卡编号。
5. 错误放置不得污染正确局面；撤销必须完整恢复手动标记与自动标记来源。
6. 每日题在同一生成器版本中可复现；生成器升级不能悄悄改变已发布日期的题目。
7. 键盘、点击、触控、刷新恢复、退出确认和 9:16 小屏路径均需浏览器验证。
8. 位图资产、声音、项目版本、SQL 记录、统一列表和独立发布网址必须通过平台现有交付检查。
