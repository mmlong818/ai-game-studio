# 下一阶段开发计划：引擎、资源与完整游戏设计

> 状态：实施中；设计/资源合同、普通项目设计合同持久化与确认摘要、首批资源入库、限定配方解析及 R5 三款资源黄金切片已完成
> 周期：六周纵向切片，不以堆叠文档或素材数量作为完成标准。

## 实施快照（2026-09-05）

- 2048：7 个运行时精灵槽位绑定 `classic-puzzle-2d`，浏览器已证明全部解码且进入画布绘制。
- 打砖块：挡板、弹球和命中特效绑定同一精选资源族，AI 与开源素材分别归档，避免来源混写。

- 每次绑定校验资源库登记、字节数和 SHA-256，并在产物写入 `_studio/CURATED_RESOURCES.json`；3D 同步写入 `THREE_ASSET_PROVENANCE.json`。
- 自动门禁已覆盖文件完整性、浏览器解码/解析和实际绘制/场景挂载；未完成槽位核验的模板不会被隐式套用。
- 资源绑定已从模板硬编码改为声明式配方：同时匹配模板、维度、运行时、玩法模式、资源角色、媒体类型、语义标签和完整状态后才会自动复用。
- 资源规划会记录命中的配方 ID；构建产物使用聚合版来源报告，保留需求 ID、配方资格、文件哈希和浏览器证据。
- 当前资源族仍保持 `reviewed`。资源库查询会区分“全局推荐”“仅限定配方可用”和“仍需审核”；目前批准三个精确配方，不批准任何整包全局自动绑定。
- 非专业工作台只显示资源准备摘要（已自动复用、系统将补齐、需关注），不暴露许可、文件格式和资源包选择。
- 可执行新手帮助已完成首个纵向切片：2048 首局以真实方向键/滑动完成两步安全练习，错误动作不推进，完成状态可恢复，并提供跳过与重看。
- 正式构建会额外执行教学浏览器门禁，验证两个成功信号、错误动作拒绝、刷新恢复、重看和跳过；证据归档到 `_studio/ONBOARDING_QUALITY_REPORT.json`。
- 虫虫攀枝也已接入同一教学合同：首步真实换道避障，次步真实头部拾取露珠并按住冲刺破树脂；教学期暂停随机压力，错误操作不会制造惩罚性失败。

## 1. 优先级

最高约束是“非专业用户最小操作获得高完成度小游戏”。每条工作流既要提升内部能力，也要减少默认创作链路中的选择、配置、等待和返工；新增能力若需要普通用户理解引擎、素材许可或专业策划参数，不能进入默认流程。

三条工作流不平均用力：

1. **P0 设计—资源共同合同**：先让每个设计状态产生明确资源需求与验收，否则资源库继续失控。
2. **P0 资源供给最小闭环**：解决当前最大缺陷，建立来源、许可、入库、检索和绑定。
3. **P0 新手与难度闭环**：把已有设计原则变成运行时和发布门禁。
4. **P1 引擎评估**：保持 PlayCanvas 主线，只做 LayaAir/GDevelop 基准，不阻塞产品改进。

## 2. 并行工作流

### A：资源供给

负责人输出：资源需求 Schema、来源登记、许可门禁、隔离入库、资源族、检索评分、预览评审和三款黄金游戏资产包。

### B：游戏设计完整性

负责人输出：GameDesignContractV1、机制课程、新手步骤、难度向量、失败辅助、内容节奏和设计探针。

### C：引擎评估

负责人输出：统一基准、PlayCanvas 数据、LayaAir PoC、GDevelop 对照和采用决策；不得先改生产路由。

三条流通过稳定 ID 汇合：设计产生 mechanic/state/level，资源绑定这些 ID，引擎适配器实现并上报相同 ID，验收据此判断。

## 3. 六周切片

### 第 1 周：合同与真实缺口

- 定义默认创作编排：一句话输入、假设补全、冲突检测、一次确认和自动执行状态。
- 定义 GameDesignContractV1 与 AssetRequirement。
- 从现有模板迁移两款样板：2048、虫虫攀枝。
- 输出两款游戏的教学、难度和资源缺口报告。
- 冻结 B1/B2/B3 引擎基准输入。

退出：能在生成前列出缺失设计项、资源状态和验收项；Schema 往返稳定。

### 第 2 周：资源来源与隔离入库

- 实现 ResourceSourceRecord、许可矩阵和 quarantine。
- 人工选择首批 CC0 3D 环境件、材质、HDRI 和原创/CC0 音效。
- 生成缩略图、接触表、转台和波形预览。
- 禁止未知许可、外链和未加工原始资源直接绑定。

退出：至少一个 2D 资源族和一个 3D 资源族完成来源到发布包追溯。

### 第 3 周：可执行新手帮助

- 实现 OnboardingStep 状态、触发、真实动作完成信号、跳过与重看。
- 接入键盘和触控差异提示。
- 给 2048 和虫虫攀枝建立前 60 秒浏览器探针。
- 教学状态自动产生所需高亮、手势、文案和音效槽位。

退出：全新存档可完成教学；提示不遮挡；移除成功信号时测试稳定失败。

### 第 4 周：难度与失败恢复

- 实现 DifficultyPlan、难度向量、机制课程和相邻阶段跳升检查。
- 实现失败原因分类、分层提示、显式辅助和重试时间预算。
- 让有限关卡、无尽和回合制使用不同内容节奏结构。
- 完成两款样板的设计人工复核。

退出：能故意制造难度断崖、未教学机制和错误失败提示，并由门禁发现。

### 第 5 周：引擎基准

- 记录 PlayCanvas/现有 2D 的三款基线。
- LayaAir 完成 B3 单页 Web PoC；只有导出完整后才尝试小游戏目标。
- GDevelop 完成 B1/B2 工程映射差异报告。
- 比较包体、启动、帧率、内存、构建、Agent 控制、许可和退出成本。

退出：每个候选有证据化评分和明确结论；生产默认引擎不变。

### 第 6 周：完整黄金切片

- 新建一款短小但完整的黄金游戏，不能复用旧游戏标题或只换皮。
- 从设计合同生成资源需求，完成获取/生成、绑定、教学、难度、失败辅助和发布。
- 桌面、手机、三浏览器、资源许可、离线包和真人试玩全部通过。
- 复盘哪些结构可复用，更新模板和能力注册表。

退出：新用户无需外部说明可完成首局；内容至少发生两次结构变化；发布包资源完整且来源清楚。

## 4. 首批工程任务

1. 新建 `src/shared/game-design-contract/`，实现 Schema、序列化、引用与缺口检查。
2. 新建 `src/shared/resource-requirements/`，从对象状态、规则反馈和教学步骤生成槽位。
3. 扩展资源来源与版本模型，不直接膨胀 GameProjectV3 单表。
4. 增加 `onboarding/progression/assistance` 验收类型和证据失效映射。
5. 实现教程运行时及 `GameProbe` 动作/事件合同。
6. 实现难度向量与课程校验器，保留旧倍率作为运行参数而非设计真相。
7. 建立资源隔离目录、许可扫描和 attribution 生成器。
8. 建立接触表、3D 转台和音频波形/响度检查。
9. 定义 EngineAdapter 和三个固定基准夹具。
10. 完成 PlayCanvas 基线后再开发 LayaAir PoC。

## 5. 发布门禁新增项

- 缺少设计合同或合同引用错误。
- 核心机制没有教学或明确豁免理由。
- 新机制第一次出现即处于高压力状态。
- 相邻内容发生无说明的多维难度突刺。
- 失败原因无法映射到提示或恢复动作。
- 发布所需资源槽位缺失、来源未知或许可不兼容。
- 资源实际格式、大小、面数、时长或哈希不符合合同。
- 引擎适配器无法上报对象、行为、规则和验收 ID。

## 6. 不进入本轮

- 不整体迁移到 LayaAir、GDevelop、Godot 或 Cocos。
- 不建设无审核的公共资源市场。
- 不批量抓取互联网素材或默认接受“免费”但无许可证的文件。
- 不用隐藏动态难度替代关卡设计。
- 不因为已有二十关框架就强迫无尽、章节或回合游戏使用二十关。
- 不把“AI 已生成”当作设计、资源或引擎验收完成。

## 7. 阶段总完成定义

- 非专业用户输入一句话创意，在无关键冲突时只确认一次，就能得到可试玩、带完整资源、新手帮助、难度递进、失败恢复和发布准备的首版。
- 普通模式不出现引擎、资源格式、许可类别、组件树或构建参数；需要时可进入不阻塞默认流程的高级模式。
- 设计、资源、实现和验收共享稳定 ID，任何变更能追踪影响。
- 资源获取成为可持续管线，而非每款游戏临时搜索。
- 新手帮助由玩家真实动作完成，不是一次性文字弹窗。
- 难度由可解释维度和机制课程驱动，不是所有数值一起上涨。
- PlayCanvas 去留与新引擎引入由同一套证据决定。
- 至少一款全新黄金游戏走通“设计 → 资源 → 构建 → 教学 → 难度 → 验收 → 发布”。
