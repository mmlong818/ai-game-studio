# 私有作品资源交付规则与封面流程修复

2026-09-07

## 根因及证据

测试项目 e19ca5e9-af58-4e3c-a77a-e4302c760cec 已有通过验收的版本 574a4dec-76b6-4496-911f-b4d98d0cfa3b，assets/cover.png 实际存在。问题并非图片生成失败：项目摘要只对已发布作品返回封面地址，未发布的可玩项目得到 null；前端随后拼接不存在的 generated 模板封面地址。

此前第 80 号文档记录的“封面资源仍不可用”现已定位为地址交付缺失，而不是产物丢失。占位只是表现容错，不能代替流程修复。

## 必须遵守的交付规则

1. 资源生成、可玩版本验收和公开发布是不同阶段；私有作品的封面与试玩交付不得依赖公开发布。
2. 已通过质量验收的未发布版本，其封面由服务端返回同一不可变版本的 assets/cover.png 地址，使用 gameOrigin，不使用 API 域名或前端推测地址。
3. 草稿不声明拥有尚未生成的图片；自由生成作品不得回退到虚构的模板资源路径。
4. 新版制作中或失败时沿用已有验收版本；新版验收成功才切换封面。历史版本查询保持历史封面。
5. 官方专用封面和已发布稳定地址的现有规则不变；本修复不自动发布、重试制作或消耗生成额度。
6. 交付检查必须覆盖列表数据到资源读取，而不只检查生成目录。占位正常显示不等于资源交付成功。

## 验证

- 新增内存数据库生命周期回归：草稿、首次完成、列表读取、修改中、修改失败、新版完成与历史版本。
- 新增无封面时不请求虚构图片的前端测试。
- 类型检查通过；82 个前端测试文件、359 项测试通过。
- 服务空闲后重启后端，真实 API 列表返回版本封面；GET 返回 200、image/png、2,278,954 字节，PNG 签名正确。项目仍未发布。
- 未调用模型，未生成新图，未变更真实项目记录；既有项目通过读取逻辑修复即可恢复。

## 范围

本次修复封面地址交付，不宣称已经加入所有资源的线上 HTTP 自动巡检，也不涉及审核责任体系重构。
